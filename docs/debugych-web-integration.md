## Изменения интеграции

1. Единый диалог создания проекта: название, исходники / ZIP и текст требований. Использует существующие project/files API. При частичном сбое повторяет оставшуюся загрузку в тот же проект. Сохранённый проект можно открыть и исправить вручную.
2. Требования можно ввести текстом в Workspace. Они сохраняются обычным Markdown-документом. Уникальное имя исключает коллизию с requirements.md внутри архива.
3. В Overview добавлена основная кнопка запуска: имеющиеся тесты запускаются без LLM, для нового проекта используется существующий autonomous endpoint и явное согласие на отправку данных / резерв расходов.
4. Добавлен выбор запуска с сохранением в URL. Ссылки последних результатов открывают конкретный run, а не произвольный последний результат.
5. Исправлено открытие исторического Verify после нового прогона. Исторический результат принимается только при совпадении fix_id и неизменяемого patch_sha256. Применение из исторического просмотра отключено. Backend дополнительно сохраняет собственные проверки.
6. Исправлено перекрытие навигации маскотом: grid-область ограничена своей шириной, projectbar переносится, вкладки занимают доступное пространство. Компактный персонаж не включает обязательную сцену со столом.
7. Ошибки связи переведены в понятное состояние Offline / повторного подключения. Health обновляется при фокусе окна и ручном повторе.
8. Добавлен запуск production dist через локальный Node HTTP server и same-origin proxy. Он слушает только 127.0.0.1, не принимает внешний upstream, отклоняет traversal и доступ к скрытым файлам. Никаких новых backend-компонентов.
9. Добавлены favicon, бесплатный release-набор тестов и скрипт записи сохранённых реальных результатов.

## Локальный запуск

Текущий проверенный адрес: **http://127.0.0.1:8798/**. API / docs доступны через этот же origin. Это production dist, не Vite dev server.

Из корня распакованного release на Windows с Node.js 22+:

```powershell
.\scripts\start-local.ps1 -ReuseBackend
```

Если 8000 уже работает, скрипт его переиспользует и не перезапускает контейнеры. Если порт 8798 занят, укажите `-Port 8799`. Скрипт не завершает чужие процессы. Ctrl+C останавливает только этот frontend и собственный WSL keepalive, но не Compose.

Если backend ещё не запущен:

```powershell
.\scripts\start-local.ps1
```

Это использует существующий docker-compose.yml, создаёт локальную .env из примера без ключа и поднимает стандартный стек. Нужен Linux Docker с зарегистрированным runsc. На Windows без docker CLI используется Ubuntu WSL. Новый runner / pipeline не создаётся. Не запускайте второй Compose с теми же портами при уже работающем backend.

Однократная настройка gVisor описана в README и `infra/install-gvisor.sh`. Установка runsc требует Linux и перезапуска Docker; запускной скрипт не выполняет её автоматически. На этой машине runsc уже установлен и проверен. Обычный Docker runtime не является fallback для недоверенных загрузок.

Пересборка исходников:

```powershell
cd apps/web
npm ci
npm run typecheck
npm run lint
npm test
npm run build
cd ../..
.\scripts\start-local.ps1 -ReuseBackend
```

Linux при уже работающем backend: `node scripts/serve-web.mjs`. Стандартный Docker Compose web остаётся доступен по своему существующему порту 8080.

Без LLM_API_KEY доступны импорт, сохранённые результаты, demo и запуск существующих тестов; новый AI-анализ недоступен с явным сообщением. Ключ задаётся только локально на сервере, не в frontend или Desktop Pet. Режим contract-test не используется как незаметная замена live.

Остаётся ограничение проверки: новый платный LLM цикл на произвольном загруженном проекте в этом этапе не подтверждён. Его существующие endpoints, согласия и budget gates подключены.
