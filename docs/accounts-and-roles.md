# Аккаунты, жюри и команда

Обновлено 30 октября 2026 года. Production включает PROJECT_WORKSPACES=1; [контракт владения и квот](project-workspaces.md). Регистрация: https://debugych.46-226-161-120.sslip.io:9443/auth/register. Вход: https://debugych.46-226-161-120.sslip.io:9443/auth/login.

## Профили и права

| Роль | Доступ |
|---|---|
| Пользователь (viewer) | Личные проекты, загрузка, AI с согласием и бюджетом, запуск тестов |
| Жюри (jury) | Личные проекты и полный QA workflow в пределах серверных ограничений |
| Команда (team) | Личные проекты, AI и runner в пределах прежних ограничений, подтверждение патчей |
| Администратор (admin) | Сопровождение всех проектов, приглашения, изменение ролей и отключение аккаунтов |
| Владелец по ключу | Сохранённый технический доступ для настройки и восстановления |

Исторически созданы отдельные стартовые профили жюри и администратора команды. Пароли и коды приглашений хранятся вне репозитория. Используйте личные аккаунты вместо общего административного пароля. Смена временного пароля обязательна только если профиль отмечен must_change; обычный вход не требует сброса.

Жюри может загружать свои проекты и запускать проверки. Платная генерация требует согласия и общего доступного бюджета. Без входа доступно публичное демо; после явного входа в гостевой режим можно загружать свои тесты без LLM.

Открытая регистрация даёт только viewer или jury. Поле `role=admin` отклоняется; роль team/admin выдаётся по одноразовому приглашению; личные проекты viewer/jury доступны без приглашения. Администратор выдаёт приглашение через «Аккаунт», срок действия 72 часа, использование однократное. Код показывается один раз, хранится только его SHA-256. Он вводится в форму регистрации, не передаётся в URL. Уже зарегистрированного пользователя администратор может добавить в команду через список участников.

## Первый вход

1. Войти под личным аккаунтом либо зарегистрироваться.
2. При требовании смены временного пароля задать свой пароль в профиле и войти повторно. Для обычной сессии этот шаг не требуется.
3. Для команды выдавать личные приглашения, не раздавать общий административный пароль всем участникам.
4. Для жюри использовать отдельный стартовый аккаунт либо личные регистрации с профилем «Жюри».

Пароль от 12 до 128 символов. Хранение: scrypt N=32768/r=8/p=1, случайная соль 128 бит и ключ 512 бит. Одновременно не более двух KDF, не более восьми попыток входа/регистрации в минуту на IP. Текущие пределы: 1000 аккаунтов, 512 сессий, 256 активных приглашений. Cookie Secure/HttpOnly/SameSite=Strict, 8 часов абсолютного срока и 30 минут бездействия. В базе сохраняются только хеши session IDs.

Смена пароля, роли и отключение аккаунта отзывают старые сессии. Самостоятельное изменение своих административных прав закрыто, чтобы не потерять последний доступ. Восстановительный вход по серверному ключу сохранён: `/auth/login?owner=1`. Административные операции такой сессии повторно проверяют актуальность ключа через backend. Ответ приложения 403 не уничтожает действующую сессию; 401 завершает её.

## Хранение и эксплуатация

SQLite находится в постоянном volume `debugych-server_web-accounts`, `/accounts/users.sqlite`, файл mode 600, каталог mode 700, uid 1000. Таблицы users, sessions, invitations, guest_history, project_owners, workspace_usage и workspace_config. Пересоздание только server-web не удаляет аккаунты. Node 22 поддерживает используемый встроенный node:sqlite, но помечает модуль как экспериментальный; это ограничение текущего runtime, не ошибка проверок.

Доверенный gateway использует отдельный read-only mount `/etc/debugych/web-auth:/run/secrets/web-auth`. Там только служебный backend-токен, mode 400/uid 1000. Песочницы, frontend и базы аккаунтов его не получают. Ключ перечитывается для рабочих запросов после проверки сессии и владельца проекта. Жюри, пользователи и гости работают с приватным backend только через эту проверку. Анонимный публичный просмотр обслуживается из фиксированного снимка без обращения к рабочему backend.

После ротации owner-токена выполнить на VPS:

```sh
sh scripts/server-sync-web-token.sh
```

Скрипт атомарно заменяет файл внутри directory bind, не печатает токен. Перезапуск Docker daemon не требуется. Невалидный/недоступный ключ закрывает рабочий доступ.

`serverctl.sh backup` теперь включает `accounts.tar.gz` вместе с PostgreSQL и файлами проектов. Он кратковременно останавливает только server-web, api и worker данного deployment и затем запускает их. Не использовать для намеренно остановленного стека. Проверенная копия: `/root/debugych-backups/20261028-accounts`. Restore-test восстановил аккаунты в отдельный временный volume, SQLite integrity_check=ok, пользователей 2. Живые данные при restore-test не заменялись.

## Ограничения

Это одна общая рабочая область доверенной команды. Личные аккаунты не создают изолированные пространства проектов. Backend по-прежнему видит служебную авторизацию владельца; отдельного аудита автора каждой операции в AI Engine пока нет. Новые публичные регистрации не получают рабочий доступ автоматически.

Пока нет email-подтверждения, самостоятельного восстановления забытого пароля, 2FA, интерфейса отзыва ещё не использованного приглашения или редактирования логина. Приглашение нужно использовать при регистрации; существующего пользователя добавляет администратор. Платный workflow при этой работе не запускался. Native Windows GUI не проверялся через computer use; настоящий Desktop transport продолжал работать.
