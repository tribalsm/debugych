# Стабильность React/Playwright в gVisor

Дата: 2026-10-21. Ветка: `release/playwright-gvisor-stability`.

## Причина и исправление

В предыдущем полном прогоне React-набор завершился сообщениями `Timed out waiting 35s for the test suite to run` и аналогичным таймаутом teardown. В сохранённом результате первый тест исчерпал 7000 мс, второй прошёл, два остальных не завершились. Ошибки инфраструктуры корректно отделялись от дефектов приложения.

Стандартная worker fixture Playwright владела Chromium. Холодный запуск браузера попадал в бюджет первого теста. После любого падения Playwright перезапускал worker и вместе с ним браузер. Поэтому обнаружение настоящих дефектов само увеличивало затраты запуска и закрытия процессов внутри общего лимита 35000 мс. На одном CPU в gVisor это оставляло мало запаса при колебаниях нагрузки хоста.

Теперь Chromium принадлежит одному заданию. `globalSetup` запускает BrowserServer на `127.0.0.1`, worker подключается через Playwright protocol, а после его перезапуска подключается следующий worker. Запуск и окончательное закрытие браузера входят в прежний `globalTimeout`. Это изменение жизненного цикла, без переноса запуска браузера за пределы общего бюджета.

Каждый тест получает штатный отдельный BrowserContext. При завершении worker соединение закрывается, но браузер остаётся во владении задания. Отсутствующий или нелокальный endpoint вызывает ошибку, без резервного запуска вне песочницы.

Не менялись:

- 7000 мс на тест, 2500 мс на assertion, 35000 мс на набор, 40000 мс внешнего ожидания Playwright, 60 секунд ожидания sandbox supervisor.
- `workers: 1`, `retries: 0`, ожидания сгенерированных тестов, исходники контрольных проектов и классификация ошибок.
- `runsc`, `network_mode: none`, 1 CPU, 1024 MiB RAM без swap, 256 PID, read-only root, non-root UID, отсутствие capabilities, `no-new-privileges`, tmpfs с `noexec`, отсутствие Docker socket и секретов в песочнице.
- Запрет внешних браузерных запросов и service workers, CSP, ограничения артефактов, coverage и серверные условия применения исправления.

## Независимая проверка жизненного цикла

`tests/compose/browser_lifecycle_probe.py` выполняет шесть проверок в настоящем gVisor. Три намеренных assertion failure заставляют Playwright менять worker. Перед каждым тестом проверяются пустые cookies и localStorage, затем в них записывается состояние. Проверяются реальные скриншоты, число PID браузера и worker.

Первые проверки нового механизма: 6 выполненных тестов, 3 passed / 3 намеренных failed / 0 infrastructure errors; worker 0, 1, 1, 2, 2, 3; один браузер; шесть скриншотов. Отдельный прогон с измерением PID завершился за 12,6 секунды. Локальные unit-тесты проверяют освобождение соединения при ошибке worker, сохранение владельца браузера и отказ при отсутствии допустимого endpoint. Эти проверки добавлены в CI.

Во время исследования один дополнительный React E2E не прошёл. Параллельно выполнялась диагностика старого Runner; первый assertion исчерпал 7000 мс, а весь результат занял 43,731 секунды вместе со сборкой проекта. Ошибка не переклассифицирована в обычный failed, результаты не исправлялись вручную. JSON и trace сохранены в `outputs/uiux-checks/gvisor-react-targeted*`. Дальнейший полный прогон выполнялся последовательно, без диагностической нагрузки и retries.

## Воспроизведение

В изолированном Compose-окружении с локальным контрактным провайдером:

```sh
node --test tests/unit/browser_lifecycle.test.cjs
docker compose exec -T supervisor python < tests/compose/browser_lifecycle_probe.py
docker compose exec -T supervisor python < tests/compose/playwright_probe.py
PLAYWRIGHT_BASE_URL=http://127.0.0.1:8082 COMPOSE_CONTRACT_TEST=1 npm --prefix apps/web run test:e2e
```

В этой рабочей копии для Compose нужны `--env-file /dev/null -p debugych-redesign2 -f docker-compose.yml -f compose.test.yml -f compose.redesign.yml`. Не использовать `.env` с настоящим провайдером. Не выполнять `up`/`down` для чужих Compose-проектов.

Для изоляции проверки используются собственные теги `debugych-redesign2-supervisor:local` и `debugych-redesign2-playwright:local`. Проверенный образ браузера построен добавлением изменённых runtime-файлов поверх существующего образа `debugych-playwright:local`, без обновления Node, Playwright 1.64.1 или Chromium. Dockerfile исходного runtime по-прежнему копирует эти файлы при обычной сборке.

## Границы результата

Проверки используют явный локальный контрактный провайдер. Они подтверждают исполнение, Bug Proof, Fix & Verify и UI-сценарии, но не качество настоящей LLM. Платных запросов нет. Основной `.env`, 3D-ветка и контейнеры других Compose-проектов не изменялись. Пользовательские проекты не переписывались; E2E применяет патч только к созданному им одноразовому проекту после проверки обоих вариантов диалога подтверждения.

Общий дедлайн остаётся жёстким: произвольно большой или зависший набор может корректно завершиться инфраструктурной ошибкой. Падение единственного браузера также остаётся ошибкой инфраструктуры. Новый image ID требует нового запуска для доказательств, привязанных к предыдущему образу; проверка соответствия образа не обходится.
