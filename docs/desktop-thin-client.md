# Debugych Desktop 1.3.0: единый web-интерфейс и native-питомец

Дата: 29.10.2026. Ветка: `release/desktop-1.3`, база `0c093d4`.

## Результат и границы

В Remote Mode главное окно получает HTML, JS, CSS и ресурсы непосредственно с настроенного HTTPS-сервера. Больше не требуется пересобирать EXE для обычных изменений web-интерфейса. Новая версия страницы загружается после перезагрузки или повторного открытия приложения, без принудительной замены интерфейса посреди пользовательской операции.

Сервер: https://debugych.89-22-232-119.nip.io:9443/. Перенос уже опубликован на сервере: пересобран только `server-web`. API, worker, PostgreSQL, gVisor, VPN и сторонние сервисы не перезапускались. Main не объединялся.

Питомец v3.2.1 остаётся прозрачным окном того же Tauri-приложения. Native-код, спрайты, чат, перетаскивание, Live Mode, общий проект и переходы к результатам сохранены. Для изменения самого питомца, системных меню, native-команд или локального backend всё ещё нужен новый установщик. Local Mode явно использует комплектный frontend и не обновляет его с сайта.

## Архитектура и безопасность

`Tauri shell -> iframe(loopback) -> доверенный Node transport -> HTTPS web gateway -> API`.

Один и тот же loopback-прокси теперь передаёт и страницу, и ресурсы, и API. В Remote Mode он не читает комплектный `dist/index.html`. Это также проверено запуском копии прокси в каталоге без frontend-файлов.

HTTPS-сертификат проверяется штатно, целевой origin фиксирован в настройках. Внешние redirect отклоняются. Host, Origin и cross-site API-запросы проверяются. Cookie/Authorization вызывающего браузера удаляются; собственный сеанс передаётся только из доверенного компонента через stdin. Set-Cookie не попадает в iframe. Удалённый React-код не получает `window.__TAURI__` и прямого доступа к Credential Manager.

Сеанс по-прежнему хранится в Windows Credential Manager, пароль не сохраняется. Native-питомец и API-прокси используют тот же сеанс. Кнопка «Аккаунт» открывает native-настройки через проверяемые source/origin/nonce сообщения. Web-формы `/auth/*` не проксируются: нельзя незаметно сменить аккаунт только в одном из окон. Регистрация и управление паролем доступны на сайте в браузере. Истёкший сеанс даёт 401 и открывает native-вход, без перехода в публичное демо от имени прежнего пользователя.

На локальном ответе снимается запрет iframe X-Frame-Options удалённого сайта, а CSP frame-ancestors ограничивается origin оболочки Tauri; остальные CSP-директивы сохраняются. Публичный сайт сохраняет свои заголовки защиты.

HTML имеет `no-store`. Хешированные Vite bundles имеют immutable cache, остальные изменяемые ресурсы требуют revalidation по ETag. При потере HTTPS-сервера выводится явная ошибка с повторной загрузкой; устаревшая локальная копия автоматически не подставляется. Это не offline-first клиент.

Дополнительно исправлена гонка native-shell: старое сообщение готовности больше не затирает ошибку входа во время фонового опроса статуса запуска.

## Ошибки при подготовке проверок

Первый запуск нового live-harness не нашёл Playwright из корня репозитория. Разрешение зависимости исправлено на существующий `apps/web/node_modules`. Следующий прогон завершился timeout ожидания заголовка Test Studio; успешный результат не был засчитан. В harness добавлены ограниченные сетевые ожидания и контроль готовности дочернего прокси. После этого полный прогон прошёл для обоих профилей без изменения ожидаемых результатов или серверных данных. Причина единичного ожидания заголовка не доказана; повторяемость в медленной сети остаётся риском.

При подготовке cache unit-теста исправлены его собственные Host и публичная fixture-конфигурация. Финальный объединённый Node-прогон выполнен с OpenSSL из Git for Windows в PATH; первоначальная команда без OpenSSL завершалась ошибкой создания TLS-fixture. Строгая проверка сертификата не отключалась.

## Установка и дальнейшее обновление

1. Завершить старую версию через её «Выход». Текущий работающий экземпляр этим этапом не закрывался.
2. Запустить `outputs/Debugych-Desktop-1.3.0-Setup.exe` либо распаковать `outputs/debugych_desktop_1.3.0_windows.zip`.
3. Выбрать «Сервер Дебагыча», войти существующим логином и паролем. Сохранённый действующий сеанс может использоваться повторно.
4. Включить «Показывать питомца на рабочем столе».
5. После последующих web-релизов достаточно перезагрузить главное окно или заново открыть приложение. Новая установка для обычного web-изменения больше не нужна.

Установщик без цифровой подписи. Ручные проверки установки 1.3.0, двух настоящих WebView2-окон, сворачивания, восстановления и drag/drop в этом этапе НЕ выполнены: работа проводилась без computer use, без прерывания установленной версии. Headless Chromium с IPC double не заменяет этот финальный Windows smoke test. Чистая Windows VM также не проверялась.

Native API и web-bridge пока не имеют формализованной версии протокола. При будущих несовместимых изменениях bridge требуется согласованный релиз оболочки. Для обновлений React-экранов, стилей и API-представлений в рамках текущего контракта новый EXE не нужен. Отдельный native/питомец auto-updater в задачу не входил.

## Воспроизведение

Использовать locked npm-зависимости. Для TLS-fixture нужен OpenSSL в PATH. Команды из корня репозитория:

```powershell
node --test tests/server/web-cache.test.mjs tests/server/web-session.test.mjs tests/server/web-accounts.test.mjs tests/server/account-gateway.test.mjs tests/server/proxy-auth.test.mjs
node --test tests/unit/desktop-bridge.test.mjs
node --test apps/pet/tests/*.test.mjs
npm --prefix apps/web test
npm --prefix apps/web run typecheck
npm --prefix apps/web run lint
npm --prefix apps/web run build
./scripts/build-windows-app.ps1
```

Для shell-теста задать `DEBUGYCH_PLAYWRIGHT_MODULE` абсолютным путём к установленному `apps/web/node_modules/@playwright/test`, затем выполнить `node --test tests/server/desktop-account-shell.cjs`. Live-harness `tests/server/thin-client-live.cjs` принимает объект `{username,password,role}` только через stdin доверенного локального скрипта. Не помещать пароли в аргументы, env, отчёты или репозиторий. Он создаёт и отзывает собственный сеанс, не запускает AI или применение патчей.
