# Готовность технического MVP «Дебагыч»

Дата проверки: 20 октября 2026. Среда: Windows / WSL2 Ubuntu, Docker Compose, PostgreSQL, Redis, Celery, обязательный gVisor/runsc. Провайдер — существующий сторонний OpenAI-compatible шлюз, модель из `.env`: `gpt-6-luna`. Ключ и модель не менялись.

## Решение о готовности

**Автономный полный цикл продемонстрирован на независимых Python и JS/TS контролях без ручной корректировки тестов или принятия отклонённых ответов разработчиком.** Python подтверждён новым live-прогоном этого этапа; JS/TS — предыдущим успешным live-прогоном, дополненным текущей offline-регрессией. Платная JS/TS серия заново не запускалась.

Техническое ядро подходит для подготовки локальной конкурсной демонстрации и перехода к UI/UX и интеграции утверждённого 3D-маскота. Это не подтверждение универсальной автономности на любых репозиториях и не готовность к публичному многопользовательскому развёртыванию. Необходимо сохранить честное отображение ошибок провайдера, неопределённости и границ поддерживаемых проектов.

Предыдущие неудачи Python сохранены в [предыдущем отчёте](../autonomous-ai-validation.md). Они не исключены из истории ради успешного результата.

## Проверка протокола

Генератор возвращает только `scenarios`. Требования присоединяются сервером из ранее извлечённого документа; ссылки requirement и framework ограничены enum. Запрещены лишние поля, неизвестные ссылки, пустой набор сценариев и непокрытые требования. Ограничения длины и числа элементов сохранены. Даже при режиме провайдера `json_object` схема передаётся в инструкции и обязательна локально.

На новом Python live-прогоне извлечение, генерация, semantic review и генерация патча успешно прошли существующие схемы. Требования, цитаты и индексы assertions проверялись локально; AST и обнаружение pytest — отдельно; выполнение — только в gVisor. Reviewer не получал реализацию, результаты продукта или oracle. Никакой ветки «разрешить всё отклонённое» нет. Неустранимая неоднозначность по-прежнему останавливает workflow со статусом `manual_review_required`.

Добавлены десять offline-протокольных проверок: обе ветки pytest/Playwright с неверным JSON, чужими ключами и лишним requirements; исчерпание повторов; три случая неверного типа индекса рецензии. Локальный адаптер дополнительно использует `model_validate_json(..., strict=True)`: строка `"0"`, boolean и float не превращаются в integer-индекс.

Последнее ужесточение типов сделано **после live-прогона**. Сохранённые неизменные live evidence Python и JS/TS повторно проходят строгий разбор offline (`mvp-strict-replay.json`); полный текущий API/browser цикл проверяется контрактным провайдером. Дополнительный платный прогон после этой однострочной правки не выполнялся. Старый JS-отчёт не хранит исходный scenario payload: для него повторно проверены сохранённые извлечённые требования и semantic review, а генерация сценариев проверена текущими контрактными тестами.

## Ошибки и ограничения, которые остаются

1. Провайдер может отвечать долго или завершаться timeout; в новой серии это случилось один раз. Запуск близок к общему дедлайну. Нельзя обещать стабильную длительность при сетевой демонстрации или скрывать повтор.
2. В совокупной автономной истории четыре workflow-попытки: две успешные (по одной на язык), две прежние неуспешные Python. Это ограниченная выборка, а не показатель общей надёжности.
3. Semantic reviewer — вероятностная проверка, даже с независимыми аргументами. Неоднозначность не устраняется автоматическим согласием. Количество тестов и 100% строк не доказывают полноту требований.
4. Проекты ограничены фиксированным runtime/зависимостями, размером и контекстом. Большие документы, сборки со сторонними пакетами и произвольные сайты не обещаются.
5. Frontend/UX, 3D-маскот, конкурсный narrative и проверка проектора ещё впереди. Нужны отдельные asset-инструкции и оценка производительности, без изменения границ безопасности и поведения AI.
6. Нет production auth, multi-tenancy, общего cancel API и широкой эксплуатационной нагрузки. До публичной публикации требуется отдельный этап.
7. Осталось upstream DeprecationWarning AnyIO; оно не привело к падению тестов.

## Подготовка демонстрации и следующие приоритеты

Функциональный объём технического ядра заморожен. Следующий этап — UI/UX и approved 3D asset, не расширение AI-возможностей.

1. Сохранить текущие source/evidence архивы и версии runtime. Для UI-полировки использовать существующие API/статусы, сохранять отдельные внешнее consent и apply-confirmation, заметный manual_review_required и реальные ошибки.
2. Интегрировать только согласованный 3D-маскот как необязательный слой: лёгкая загрузка, reduced motion, fallback при недоступном WebGL, сохранение читабельности proof/diff и отключаемые реплики. Пока это задачи, не выполненная функция.
3. Пятиминутная демонстрация: проект и документ → автономный QA → Gherkin/план → 15 passed / 2 failed → Bug Proof → diff → 17/17 + oracle → показать, что исходник не изменён. Затем коротко показать JS/TS evidence и скриншоты. Oracle — независимая оценка, не подсказка AI.
4. Перед выходом проверить health/модель/runsc и доступность провайдера. Для предсказуемого показа открыть сохранённый **реальный live-run**; новый платный запуск — только в отдельно согласованном бюджете. При недоступной сети честно показать сохранённые результаты или явно обозначенный Demo Mode.
5. Репетиция на конкурсном экране: размер шрифта, пустые/долгие/error состояния, доступность diff, экспорт, история попыток и отсутствие секретов на экране. Не нажимать apply на исходном проекте без отдельного решения пользователя.
