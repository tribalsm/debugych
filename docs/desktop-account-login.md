# Desktop 1.2.2: вход по аккаунту сайта

Проверено 29 октября 2026 года. Ветка `release/desktop-account-login`. Merge в main не выполнялся.

## Что изменено

Обычный вход в Desktop использует тот же логин и пароль, что сайт. Адрес по умолчанию: https://debugych.89-22-232-119.nip.io:9443. На новом компьютере серверный ключ не требуется. Remote Mode не запускает локальный backend, WSL или Docker.

Пароль отправляется native HTTPS-клиентом в `/auth/sign-in`. Redirect выключен, TLS-проверка сохранена. Ввод очищается перед IPC и после ответа. Windows Credential Manager хранит непрозрачный session ID и метаданные профиля; пароль не сохраняется. Сеанс привязан к HTTPS origin и отделён от старого owner-key. Команды авторизации разрешены только главному native окну и не возвращают секрет через IPC.

Главное окно и питомец используют одинаковый источник авторизации: blocking HTTP для main/readiness, async HTTP для pet, собственный Node proxy для React. В proxy сеанс передаётся через private stdin, не argv/env. Сторонние Cookie/Authorization удаляются, cookie аккаунта добавляется доверенным компонентом. Proxy проверяет Host, Origin и Fetch Metadata до подстановки полномочий. Для разрешённых запросов аккаунта устанавливается Origin сервера. Ответные Set-Cookie не попадают в React.

Сервер применяет прежние роли. Жюри/viewer получают сохранённый demo snapshot и 403 на команды изменения. Team/admin получают общую рабочую область по текущим правам. Профиль просмотра разрешён в startup, но не выдаётся за готовность исполнительной среды: диагностика runner, Playwright и AI показывает «Не требуется». Для рабочего режима обязательная проверка gVisor сохранена.

При успешном переключении на аккаунт старый owner-key для этого origin удаляется. Сеанс аккаунта имеет приоритет даже при наличии старого ключа; повреждённая или истёкшая сессия не приводит к fallback на ключ. Выход удаляет обе записи, завершает owned frontend proxy, отменяет запросы pet и очищает выбранный проект. При изменении аккаунта сбрасывается ревизия общего контекста, а старый iframe закрывается.

Сервер получил opt-in header `X-Debugych-Require-Session`: запрос Desktop со старой cookie возвращает 401, а не анонимный snapshot 200. Публичный браузерный demo без этого header сохранён. Событие истечения сеанса проходит из React через существующую origin/session-bound bridge и открывает форму повторного входа. Nonce iframe в URL является только связкой окна, не session ID авторизации.

Локальный режим и резервный owner-key сохранены. Резервный ключ спрятан в дополнительных настройках для оператора. При обновлении существующий legacy-вход может продолжить работать до явного входа в аккаунт; после входа жюри старые полномочия не подхватываются.

## Установка и ограничения

Использовать `Debugych-Desktop-1.2.2-Setup.exe`, а не 1.2.1. Сначала закрыть прежний Дебагыч через «Выход». Установщик не завершает чужие процессы принудительно. В «Подключение / аккаунт» выбрать сервер, ввести аккаунт сайта и нажать «Войти / подключиться». Уже действующий сеанс возобновляется без ввода пароля. Сроки сессий остаются серверными: до 8 часов и 30 минут бездействия, затем повторный вход.

Полная ручная проверка двух настоящих native окон, установки поверх запущенного пользовательского экземпляра, перетаскивания питомца и визуальных переходов в этой итерации не выполнялась: computer use не использовался. Проверены реальный native transport, сборка и headless shell. Существующая установленная 1.2.1 не заменялась и не закрывалась принудительно.

Сборка не подписана коммерческим сертификатом. Сохраняются прежнее предупреждение Rust об unused page_url и предупреждение Vite о размере 3D chunk. Доступ команды остаётся общим workspace, не многопользовательской изоляцией проектов. Смена пароля и регистрация выполняются на сайте; временный пароль с обязательной сменой нужно сначала заменить там.
