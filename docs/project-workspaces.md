# Личные проекты и гостевая история

Проверено 29 октября 2026 года. Ветка `feature/project-workspaces`.

## Поведение

- Без входа по умолчанию открыт прежний публичный демо-проект только для просмотра.
- Кнопка «Загрузить свой проект без регистрации» создаёт отдельную гостевую историю. Она доступна также со страницы входа.
- История сохраняется в том же браузере между посещениями. Защищённая cookie живёт 30 дней после последнего обращения. Срок обновляется и в SQLite, и в cookie.
- Очистка cookie, приватное окно или другой браузер не позволяют восстановить прежнюю гостевую историю. Проекты удаляются после истечения 30 дней без активности. Активные задания сначала завершаются.
- Вход или регистрация из действующей гостевой истории переносят её проекты в аккаунт. Прежняя гостевая cookie перестаёт работать. У проекта сохраняются ID и результаты.
- Выход из гостевого режима требует отдельного подтверждения потери истории и ставит проекты на удаление. Простое закрытие вкладки ничего не удаляет.
- Пользователи, жюри и участники команды могут создавать личные проекты, загружать файлы, выполнять проверки, открывать результаты и удалять свои проекты. Администратор и владелец имеют доступ ко всем проектам для сопровождения сервиса.
- Зарегистрированные проекты не удаляются по гостевому сроку. Предыдущие проекты без записи владельца доступны администратору, автоматически жюри не раскрываются.

## Запуск без платного AI

Гость загружает исходники и собственные `test_*.py`, `*_test.py`, `*.spec.ts`, `*.test.js` и поддерживаемые расширения JS/TS. Затем нажимает «Импортировать тесты без AI» и «Запустить тесты».

Импорт не выполняет загруженный код в backend. Python разбирается через AST. Код выполняется только существующим gVisor Runner без сети. Набор отмечен `uploaded-user-tests`, начальный статус `not_run`. Импорт не означает проверку ожиданий по документации. Gherkin, проверенные требования и полноценная LLM-валидация для такого набора не выдумываются. Ошибки тестов не становятся автоматически подтверждёнными дефектами.

После импорта набор автоматически не заменяется. Для другого набора можно создать новый проект. Для AI-генерации из требований нужен вход; сохраняются прежние подтверждение передачи очищенного кода, модель и финансовые лимиты. Гостям недоступны платный AI-чат и генерация патчей. Подготовленное демо запускается без LLM. Применение патча всегда требует существующего серверного подтверждения.

Ограничения Runner сохранены: фиксированные зависимости, однородный pytest или Playwright, отсутствие npm/pip install и произвольных dev-серверов. Для браузера нужен `index.html` в корне. Используйте встроенный Playwright `baseURL`, без относительных импортов из теста. Python использует абсолютные импорты. Проекты, которым необходимы иные зависимости/инфраструктура, могут завершиться ошибкой выполнения.

## Безопасность и эксплуатация

`PROJECT_WORKSPACES=1` включён в production overlay. Владение проектами и гостевые идентификаторы хранятся в существующем приватном томе `web-accounts`, SQLite `users.sqlite`. Секретная cookie имеет Secure, HttpOnly, SameSite=Strict; в БД хранится её SHA-256, а не исходное значение. IP учитывается только через SHA-256 с устойчивой случайной солью.

Gateway фильтрует списки и проверяет владельца для проектов, тестов, запусков, ошибок, экспортов и артефактов. Неизвестные API-пути закрыты. Вложенные ссылки дополнительно проверяются backend. Изменения требуют точный Origin. Владелец может использовать прежний защищённый Bearer-доступ; этот ключ браузерным пользователям не выдаётся. API остаётся приватным, nginx перезаписывает `X-Real-IP`.

Существование таблицы владельцев автоматически включает разграничение даже без флага. Нельзя откатывать gateway к версии без проверки владельцев при сохранении новых пользовательских данных. Для отката UI оставляйте новый gateway; при откате новых API-методов импорт и очистка завершатся ошибкой, без открытия чужих данных. Сохраняйте вместе резервные копии PostgreSQL, файлового хранилища и SQLite аккаунтов/владельцев.

Лимиты: гость до 3 проектов, 64 МБ исходников, 5 попыток запуска в сутки; дополнительно 10 запусков на IP и 30 гостевых запусков в сутки на сервис. До 3 новых гостевых историй на IP в сутки, 20 на сервис и 100 активных историй. Обычный аккаунт до 20 проектов, 256 МБ исходников и 30 попыток запуска в сутки. Совокупно до 40 запусков обычных рабочих областей в сутки. Администратор освобождён от дневного лимита обычного аккаунта, но прежний бюджет AI не увеличен. Неудачные попытки тоже учитываются.

Одновременно gateway допускает две загрузки и ограничивает конкурентные запуски. Supervisor по-прежнему выполняет один sandbox за раз. Перед мутациями проверяется ограниченная оценка общего хранилища: файлы и консервативная оценка JSON. При 1792 МБ новые мутации блокируются с запасом до 2 ГБ; удаление остаётся доступным. Для загрузки заранее резервируется максимальный размер распакованного архива. Эти лимиты могут ограничивать нескольких гостей за одним NAT.

Очистка выполняется раз в 5 минут, при запуске gateway и по обращениям к API, небольшими порциями. Активные проекты не удаляются. Удаление опирается на принадлежащие проекту UUID-файлы, не на пользовательские пути. Повреждение/утрата cookie не означает немедленное удаление: данные ждут истечения срока. Сборщик требует работоспособного API и доверенного служебного ключа; ошибки не превращаются в снятие ограничений.
