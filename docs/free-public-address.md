## Что изменено

Выбран бесплатный поддомен sslip.io без регистрации аккаунта и без передачи токенов внешнему DNS-сервису. Он разрешается в 89.22.232.119 обычным DNS в проверочной Windows-среде. Это альтернативное имя на инфраструктуре nip.io/sslip.io, не независимый платный домен и не гарантия доступности из каждой сети. При смене IP потребуется другой адрес. [Описание сервиса](https://nip.io/).

Выпущен отдельный сертификат Let's Encrypt, действительный до 28 января 2027 года, 05:14 по Томску (27 января, 22:14 UTC). nginx обслуживает новое имя на 9443. HTTP на 80 перенаправляет на HTTPS с явным портом; ACME challenge остаётся доступным через webroot. Образец активного vhost: [nginx-sslip.conf.example](../infra/server/nginx-sslip.conf.example).

Порт **443 остаётся VPN-службе xray/VLESS/REALITY**. Ни её конфигурация, ни listener, ни systemd-unit не менялись. PID xray 36039 и SHA256 конфигурации совпали до и после работ. Это проверка неизменности службы; полноценный повтор подключения отдельного пользовательского VPN-клиента не проводился.

На VPS пересоздан только server-web данного deployment. API, worker, supervisor, PostgreSQL, Redis и runner не перезапускались. Бюджет и модель LLM сохранены.

## Совместимость и безопасность

Новый PUBLIC_ORIGIN задан в приватном production.env. Старый адрес `https://debugych.89-22-232-119.nip.io:9443` добавлен явным PUBLIC_ORIGIN_ALIASES. Старый HTTPS-vhost и сертификат сохранены.

Один gateway обслуживает оба разрешённых адреса, поэтому не появляются второй backend и независимые лимиты исполнения. Для каждого запроса Origin должен совпадать именно с его Host. Например, POST на sslip.io с Origin nip.io запрещён, даже если оба имени разрешены. Произвольные Host, HTTP origins, пути, userinfo и wildcard aliases не допускаются. CORS не расширялся.

Аккаунты, хэши паролей, владельцы проектов и результаты находятся в прежних хранилищах. Сброс пароля не требуется. На новом сайте нужно войти прежним логином и паролем. Cookie имеют Secure/HttpOnly/SameSite=Strict и не получают Domain: сессии не открываются всем поддоменам sslip.io.

Гостевая cookie старого имени не переносится в новый домен автоматически. Для сохранения старой гостевой истории войдите в аккаунт на старом адресе, затем в тот же аккаунт на новом. Старый адрес оставлен для совместимости; проблема его DNS может сохраняться в отдельных сетях.

Для Desktop 1.3 укажите новый URL в настройках подключения и выполните обычный вход. Настольный питомец продолжает использовать общий backend и аккаунт приложения. Bootstrap-конфигурация для следующих сборок обновлена. Установленное приложение не переустанавливалось, его пользовательская конфигурация и Credential Manager автоматически не переписывались.

- HTTP 80: 301 на новый HTTPS URL. nginx -t прошёл, reload выполнен без перезапуска VPN.
- Node gateway/accounts/history: **8 passed**, включая миграцию между двумя явными origins и запрет cross-origin POST.
- Desktop bridge и TLS proxy: **12 passed**. Headless native-shell contracts: **5 passed**.
- Настоящий HTTPS-вход жюри через браузер прошёл. Загрузка собственных Python и JS файлов, импорт тестов и запуск в gVisor: **pytest 2/2**, **Playwright 1/1**, runtime runsc. Подмена Origin со старого адреса дала 403. Для созданных проектов AI statistics показала 0 попыток. Временные проекты удалены.
- Транспорт Desktop проверен из Windows: реальный Node loopback-прокси получил HTML, ресурсы и API с нового HTTPS origin через защищённую stdin-сессию. Cookie не попала в frontend, проверка TLS не отключалась. Это не проверка настоящих окон Tauri или перетаскивания питомца.
- Публичный режим: **10 браузерных проверок** Dashboard, проектов, Test Studio, Bug Proof, diff, сохранённой проверки исправления, отчёта, mobile и входа/регистрации. Пять запрещённых команд получили 403, чужой проект скрыт, JS-ошибок нет, патч не применён.

Полный гостевой цикл на новом домене этим прогоном не подтверждён; аккаунтный цикл проверен отдельно. Общие квоты старого и нового имени сохранены.

Платных LLM-запросов и применений патчей не было. Скриншоты и JSON проверок находятся локально в outputs/server10/free-domain. Новый CI запускается на этой ветке; результаты предыдущего коммита не выдаются за результаты нового кода.

## Сертификат и восстановление

Первый запрос к CA дошёл до finalize и завершился ReadTimeout. Повторный запрос с IPv4-транспортом успешно выпустил сертификат, без отключения TLS. Обычный dry-run продления также завершился ошибкой. Прямой IPv6-запрос к ACME staging не смог подключиться; системный IPv6 и VPN не менялись. Отдельный IPv4 dry-run нового сертификата успешно прошёл вместе с nginx deploy-hook. Первоначальные ошибки не исключаются из отчёта.

Deploy-hook разрешает reload nginx для двух явных certificate lineages: старого nip.io и нового sslip.io. Общий certbot.timer сохранён. Добавлен отдельный debugych-certificate-renew.timer, который ежедневно проверяет только новый сертификат через IPv4. Его service завершился с Result=success / ExecMainStatus=0. Wrapper не отключает проверку TLS, не меняет другие сертификаты и не принуждает досрочный выпуск. Три unit-проверки фиксируют certificate scope, транспорт и восстановление состояния при ошибке. VPN hook не затрагивает.

Резервная копия исходной nginx-конфигурации, production.env, gateway/Compose, hook, согласованной SQLite аккаунтов и сведений о xray сохранена на VPS в закрытом `/opt/debugych/backups/free-domain-20261030`. Предыдущий образ server-web закреплён отдельным rollback-тегом. Резервные копии и ключи в Git не включены.

Откат: отключить только debugych-certificate-renew.timer и убрать только новый nginx-vhost, восстановить прежние gateway/Compose/environment и hook из копии, проверить nginx -t, затем выполнить reload nginx и пересоздать только server-web. Не останавливать xray, Docker daemon, базы или runner. Аккаунты при этой миграции не изменялись и не требуют отката базы без отдельной причины.

## Оставшиеся ограничения

Адрес содержит IP и порт 9443. Если сеть посетителя блокирует этот порт, DNS-изменение не поможет. URL без нестандартного порта потребует отдельной маршрутизации с сохранением VPN либо второго публичного IP; в этой работе 443 не перенастраивался. Доступность с независимого российского мобильного/корпоративного подключения пока не проверена.
