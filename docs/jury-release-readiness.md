Ветка аудита анимаций не включена; GLB, питомец и техническое ядро не менялись.

## Что исправлено

2. В публичный каталог добавлены два новых подготовленных проекта с настоящими сохранёнными наблюдениями gVisor. Старый Server 1.0 offline control и его ссылки сохранены.
3. На главной появился архив настоящих Python/JS live AI-прогонов от 20 октября. Он загружается по явному нажатию и не выполняет LLM-запросов.
4. API-ссылка скрыта до проверки подключения, в публичном и гостевом режиме. Для авторизованных рабочих областей ссылка сохранена. Прямой анонимный доступ к защищённой схеме не открывался.

Проценты сохранены такими, какими их вернул инструмент. Python percent_covered включает знаменатель ветвей, поэтому он не обязан совпадать с 6/8 строк. Тесты не менялись ради нужного процента или успешного исправления. Оригинальные функции остались дефектными; исправление проверялось в отдельных копиях. Эти тесты подготовлены разработчиком, не AI.

Скрипт `scripts/build-public-controls.py` выполнил восемь отдельных заданий через существующий trusted supervisor, прежние профили и runsc. Не выполнялись pip/npm install из проектов, сетевые запросы песочницы, новые LLM-вызовы или apply-fix. Каждый язык закреплён на одном image_id. `scripts/package-public-controls.py` сверяет полный fingerprint каждого фактического входа, включая job ID и expected image, и сохраняет отдельные source/test digests для сравнения повторов. Сравнивать job fingerprints напрямую нельзя, потому что ID каждого задания новый.

Snapshot находится в `infra/server/public-demo.json`, доступен только через точный frozen allowlist GET/HEAD. Каталог ограничен восемью уникальными проектами. POST, удаление, генерация и применение патчей в публичном режиме остаются запрещены. Данные личных проектов не добавлялись в allowlist.

## Историческая настоящая AI-генерация

Публичный файл `apps/web/public/evidence/live-ai.json` построен allowlist-упаковщиком `scripts/package-live-evidence.py` из сохранившихся отчётов и ZIP. Он содержит только сгенерированные тесты, доступные Gherkin, diff, измеренные до/proof/после, статистику ошибок и SHA-256 исходных файлов.

- Python: 20 октября, gpt-6-luna, 4 модуля; 15/2 до, 17/0 после; 5 запросов, из них 1 временная транспортная ошибка с последующим автоматическим повтором.
- JS/TS: 20 октября, gpt-6-luna, 4 модуля; 2/2 до, 4/0 после; 4 запроса, ошибок запросов в этой записи 0.
- В обеих успешных записях manual_interventions=0, тесты неизменны, оригинальный патч не применён. Две прежние неуспешные Python workflow-попытки явно названы, история не скрыта.
- Gherkin-текст отсутствует в сохранившейся JS-записи. Вместо выдуманного сценария UI сообщает об отсутствии и показывает настоящие исполняемые тесты.
- Приватные oracle, `.env`, ключи, provider prompts, пути приватного хранилища и consent fingerprints не публиковались. Фактическая стоимость провайдера недоступна, резерв бюджета не выдаётся за списание.
- Это ограниченная историческая проверка контролей. Она не доказывает универсальную надёжность и не подтверждает новый live RAG workflow. Модель указана по метаданным выбранного стороннего провайдера, без независимой аттестации его инфраструктуры.

## Проверки кандидата

Локально: TypeScript, ESLint, production build; 12 frontend unit; 5 существующих gateway/account/workspace проверок и 2 новые проверки каталога/provenance. В первой целевой браузерной серии 14 прошли, 2 новых сценария упали из-за неоднозначного селектора непокрытых строк двух TS-файлов. Селектор привязан к нужному файлу, повтор новых сценариев 2/2 успешен. Ошибочная проверка равенства runner fingerprints заменена проверкой связанных input/source/test digests, без изменения реальных наблюдений.

Полный CI кандидата: [checks этой ветки](https://github.com/tribalsm/debugych/actions/workflows/ci.yml?query=branch%3Afix%2Fjury-release-demo). Незавершённый запуск не считается успешным. Подробности production-проверки и итоговые номера прогонов фиксируются после завершения.

## Как показать

1. Без входа открыть главную и архив live-прогонов. Назвать дату, модель, успешные и ошибочные запросы; показать настоящий AI-тест и diff.
2. Выбрать новый Python-проект: Test Studio, реальное падение границы, Bug Proof, проверенный diff и регрессию. Не нажимать применение.
3. Выбрать TypeScript: Playwright-тест, затем Reports, Istanbul/source maps, выполненные и непокрытые строки rules.ts, строки/ветви.
4. Для своего проекта войти или создать гостевую историю. Гость запускает загруженные тесты без LLM. Новый AI-запуск требует аккаунта, отдельного согласия и прежнего бюджета.
