# Дебагыч: проверка требований кейса №9

30 октября 2026. Матрица составлена по доступному пользовательскому ТЗ и присланному аудиту. Отдельный официальный комплект материалов организаторов не предоставлен. Это техническая самооценка с воспроизводимыми ссылками, не официальный вердикт жюри.

| Критерий | Реализация и доказательство | Граница |
|---|---|---|
| 1. Генерация Gherkin | services/ai/engine.py, строгая схема Plan/Scenario, Test Studio; tests/integration/test_autonomous.py | Текущие проверки новых изменений используют контрактный провайдер; это не новая live-валидация GPT |
| 2. Генерация и запуск автотестов | pytest и Playwright, неизменяемые снимки, gVisor; tests/compose/user_import_smoke.py | Фиксированные зависимости; Java execution отсутствует |
| 3. Визуализация покрытия | Reports: процент, файлы и выполненные/непокрытые исходные строки; tests/compose/source_map_smoke.py | Только инструментированные загруженные модули, не все возможные пути приложения |
| 4. coverage.py / Istanbul | Python lines/branches; esbuild source maps + Istanbul для исходного JS/TS/TSX | При отсутствии достоверной карты явный fallback на compiled JS; старые отчёты не переписываются |
| 5. Экспорт | Gherkin/Python/JS, QA JSON, JUnit XML, GitHub Actions package; tests/integration/test_ci_exports.py | Скачанный CI-клиент проверен через HTTPS; чужой GitHub-hosted pipeline отдельно не запускался |
| 6. QA dashboard | Dashboard/Reports, фактические результаты, покрытие, история, раздельные case pass rate и run success rate | Повторы учитываются отдельно; успех не доказывает полноту тестирования |
| 7. Compose и архитектура | scripts/start-compose.sh, read-only preflight, FastAPI/PostgreSQL/Redis/Celery, собственные образы | Хост должен заранее иметь Linux Docker, Compose и runsc; универсальная установка gVisor одной командой не заявляется |

Дополнительно: pgvector и локальные мультиязычные эмбеддинги с текстовым fallback реализуют условный пункт раздела 6 пользовательского ТЗ. См. [поиск](project-retrieval.md). Его обязательность в официальном чек-листе отдельно не подтверждена.

Bug Proof и Fix & Verify демонстрируют воспроизведение, ожидаемый/фактический результат, diff, повторный тест и регрессию. Проверка выполняется в копии. Применение к оригиналу требует отдельного подтверждения и в публичной демонстрации не выполняется.

## Что показать за 2-3 минуты

1. Открыть [стенд](https://debugych.89-22-232-119.sslip.io:9443/), выбрать подготовленное демо. Назвать его подготовленным, не live AI.
2. Test Studio: требование, связанный тест, фактическое падение и результаты запуска.
3. Bug Proof: ожидаемый результат, наблюдение, воспроизводимый тест и traceback.
4. Fix & Verify: минимальный diff, проверенный патч и регрессия. Не нажимать применение.
5. Reports: pass rate и run success отдельно, исходные строки TypeScript на новом контрольном прогоне, JUnit и CI package.
6. Если время позволяет: личный проект и локальный поиск русским запросом по английским требованиям. Показать метод pgvector-semantic и явно назвать локальную embedding-модель, а не LLM-генерацию.

Для новой AI-генерации нужны аккаунт, согласие и доступный бюджет провайдера. Запускать её на защите стоит только после отдельной разрешённой бюджетной проверки. Исторические live benchmark не выдаются за сегодняшнюю проверку новых RAG-изменений. Desktop и питомец дополнительные, ядро демонстрации остаётся QA workflow.
