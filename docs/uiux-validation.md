## Реализовано

- Единые цветовые, типографические и размерные токены в `product.css`. Графитовая тема, синий акцент, семантические статусы, контрастные кнопки и фокус.
- Компоненты `Dialog`, `Tabs`, `CodeView`, `StatusBadge`, `EmptyState`, `Skeleton`; обработка отказа clipboard. Prism разбирает текст в React-узлы, исходники не вставляются как HTML.
- Focus trap, Escape, возврат фокуса, мобильное меню с inert для скрытой навигации, skip link, управление вкладками стрелками/Home/End.
- Пользовательское отключение декоративного движения и поддержка prefers-reduced-motion.
- Ошибки загрузки с именем файла; сохранённые файлы остаются видимыми при частичном отказе. Ограничение размера проверяется также до отправки, серверная проверка остаётся обязательной.
- Toast с явным закрытием, skeleton, пустые состояния, повторное подключение после сетевого отказа.
- Статусы Generated, Validated, Running, Passed, Failed, Infrastructure Error и Manual Review Required не сводятся в один результат.
- Validated привязывается к сохранённому проверенному плану и точным текущим коду теста/требованиям. Старого validation_id недостаточно после редактирования.
- Bug Proof показывает требование, ожидаемое/фактическое, путь/строку от backend, воспроизводимый тест, traceback, исходный запуск и доступные браузерные артефакты. Критичность не придумывается.
- Fix & Verify сохраняет просмотр diff, исходный прогон, проверку после патча, регрессию, историю версий, серверные ID и hash. Применение требует подходящей завершённой проверки и отдельного подтверждения пользователя.
- Reports не вычисляет отсутствующие проценты требований и не заменяет данные статистикой демо. Покрытие собранного JS явно отделено от исходного TS; отсутствие данных отображается как отсутствие данных.

Промежуточные прогоны нашли:

1. Дублирование названий теста в списке и редакторе делало старый getByText неоднозначным. Селекторы уточнены до heading; проверки результатов и явного применения сохранены.

Попытка установить max_calls=20 была отклонена строгой конфигурацией, исправлено на разрешённые 6. Прогон в ошибочном окружении прерван, его результаты не выдаются за регрессионное подтверждение.
3. Focus restore диалога конфликтовал с autoFocus вложенного input. Фокус теперь полностью управляется Dialog.
4. Axe обнаружил недостаточный контраст синих кнопок и статусов сохранённых файлов. Цвета исправлены, правила axe не отключены.
5. Выбор ошибки терялся после обновления рабочего пространства. Выбор сохраняется по project ID, проверен полным JS/TS сценарием.
6. Старые ID валидации сохраняются API при редактировании. Backend не менялся; отображение статуса проверяет точное соответствие сохранённому плану, добавлен отрицательный тест.

7. При повторном выборе уже активного проекта обработчик очищал тесты, но selected не менялся и загрузка не повторялась. Повторный production-прогон обнаружил эту гонку. Tailwind ограничен исходниками `src`, чтобы HTML-отчёты E2E не влияли на production CSS.

## Изолированное окружение

`compose.uiux.yml` применяется только вместе с `compose.test.yml` и именем проекта `debugych-uiux`. У него отдельные PostgreSQL, Redis, project-data, runner-token и сети. API: 8011, production web: 8081, Vite: 5181. Настоящий `.env` не копируется и не читается, используется `--env-file /dev/null` в WSL. Контрактные ответы маркируются в интерфейсе. Запуски pytest/Playwright фактические, но это не повторное доказательство качества живой LLM.

```sh
docker compose --env-file /dev/null -p debugych-uiux \
  -f docker-compose.yml -f compose.test.yml -f compose.uiux.yml \
  build api runner supervisor web
docker compose --env-file /dev/null -p debugych-uiux \
  -f docker-compose.yml -f compose.test.yml -f compose.uiux.yml \
  up -d --no-build api worker llm-stub web
```

Образы `debugych-sandbox:local` и `debugych-playwright:local` должны быть заранее подготовлены существующей инфраструктурой gVisor. Здесь они используются без пересборки. Не выполнять общий `docker compose build`, `down`, `down -v` или очистку Docker хоста другого процесса.

```powershell
Set-Location apps/web
npm ci
npx playwright install chromium
npm run typecheck
npm run lint
npm run build
$env:PLAYWRIGHT_BASE_URL='http://127.0.0.1:8081'
$env:COMPOSE_CONTRACT_TEST='1'
npm run test:e2e
```

Для отдельного dev-сервера: `$env:API_TARGET='http://127.0.0.1:8011'`, затем `npm run dev -- --port 5181 --strictPort`.

## Границы проверки и оставшиеся задачи

- Axe и клавиатурные сценарии не являются сертификатом полного соответствия WCAG. Ручная проверка screen reader, Safari, Firefox и touch-устройств остаётся отдельной задачей.
- Контрактный провайдер проверяет интеграцию UI, а не способность настоящей LLM находить новые ошибки. Платных запросов на этом этапе нет.
- Полная ширина кода и таблиц на телефоне доступна внутренней горизонтальной прокруткой. Большие доказательства остаются длинными; навигация по трём этапам сокращает переход к diff и проверке.
- Глобальное управление запросами остаётся в App; полноценный query cache, отмена запросов при смене проекта и виртуализация больших наборов не добавлялись.
- Поиск каталога показывает первые восемь совпадений, полный список доступен через selector проекта. Серверной пагинации нет.
- Качество требований показывается из последнего исходного запуска с валидным наблюдением и явным ID; оно не пропадает из-за последующего verify без поля quality. Покрытие требований означает связь с выполненными assertions, а не семантическую полноту. Mutation score не рассчитывается.
- Для обычного AI-анализатора без полного автономного валидатора нельзя обещать Validated. Ручное редактирование не запускает платную повторную генерацию.
- Файл ошибки и линия показываются в точности по API; иногда backend указывает сгенерированный тест, а не место причины в приложении.
- UI не загружает модель. Контракт будущей интеграции описан в [uiux-mascot-contract.md](uiux-mascot-contract.md).

## Безопасное объединение

Не переключать и не сбрасывать исходное незавершённое дерево `release/ui-3d`. Сначала владелец 3D-процесса должен сохранить его изменения собственным commit.

Затем создать третью интеграционную ветку/worktree от согласованного commit задачи А и выполнить cherry-pick commit задачи Б. Конфликты `main.tsx`, `product.css`, `package.json`, `package-lock.json` и пересекающихся E2E разрешать вручную: оставить API-поведение этой ветки, сохранить необходимые зависимости 3D-процесса и подключать renderer через MascotSlot отдельным изменением. Не копировать `apps/web` целиком и не заменять чужие GLB/manifest/components. После согласования зависимостей обновить lockfile и повторить сборку, lint и весь E2E-набор.

Незакоммиченные 3D-тесты другого дерева не переносились и не запускались. После подключения renderer их нужно выполнить вместе с UI-набором. До согласования ветки не объединены. Для просмотра использовать отдельный порт проверочного окружения.
