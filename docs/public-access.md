# Доступность публичного адреса

Основной URL с 30 октября 2026 года: https://debugych.89-22-232-119.sslip.io:9443/

Бесплатный поддомен направлен на тот же VPS. Обычный DNS в проверочной Windows-среде возвращает 89.22.232.119. HTTPS отвечает 200 с включённой проверкой сертификата. Сервис не требует входа в VPN для авторизации; VPN-служба на 443 не менялась. Порт сайта остаётся 9443.

Аккаунты и проекты общие со старым адресом. На новом домене войдите заново прежним логином и паролем: cookie и сохранённые Desktop-сессии привязаны к origin. Гостевая история старого домена не переносится cookie автоматически; сохраните её в аккаунт на старом адресе, затем войдите в этот аккаунт на новом.

[Настройка и результаты проверки](free-public-address.md). Доступность из независимой российской мобильной/корпоративной сети ещё не подтверждена.

## Диагностика прежнего адреса

Проверка 30 октября 2026 года: https://debugych.89-22-232-119.nip.io:9443/.

- Обычный DNS из проверочной Windows-среды возвращает ошибку имени, в том числе при запросах с указанием 1.1.1.1 и 8.8.8.8.
- Google DNS через HTTPS возвращает A-запись 89.22.232.119. Это не подтверждает работу DNS через любой провайдерский или VPN-маршрут.
- HTTPS-запрос с принудительным разрешением имени в этот IP отвечает HTTP 200. Проверка сертификата включена и успешна; -k не используется.
- На VPS nginx слушает 9443, а 443 занят xray. Эти службы не перенастраивались.

Это свидетельство проблемы доступности по некоторым DNS-путям, а не доказательство общей недоступности сервера или точной причины ошибки. Проверка с независимого устройства и мобильного интернета остаётся открытой.

Для диагностики транспорта без изменения DNS компьютера:

```sh
curl --resolve debugych.89-22-232-119.nip.io:9443:89.22.232.119 \
  --connect-timeout 6 --max-time 12 -I \
  https://debugych.89-22-232-119.nip.io:9443/
```

Команда проверяет HTTPS с исходным именем и SNI. Её успех не означает, что посетитель сможет открыть обычную ссылку. Не отключайте проверку сертификата и не добавляйте пароль или API-ключ в URL.

## Выбор адреса

Предпочтителен управляемый домен или DNS-поддомен, направленный на VPS. Нужно отдельно согласовать имя и проверку доступности стандартного HTTPS-порта. Перенос на 443 требует сохранения действующего VPN: нельзя просто остановить xray или заменить его listener nginx-сервером.

GitHub Pages предоставляет адрес для статических HTML/CSS/JS на своей инфраструктуре, а не DNS-имя, которое можно направить на этот VPS. Размещение там React потребует отдельной адаптации API, cookie и авторизации; доступный HTTPS-адрес backend всё равно нужен. Поэтому Pages само по себе не решает текущую проблему. [Документация GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages).

Короткая ссылка или QR-код также не исправляют DNS и блокировку порта назначения. Новый адрес уже подключён, старый оставлен совместимым. VPN и учётные данные не менялись.
