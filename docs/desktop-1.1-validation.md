## Исходная архитектура

Основа основного Windows-приложения: `release/windows-main-app`, commit `94462094b1ce612d43c1766d72edcc983112e54a`. Питомец: отдельный репозиторий Desktop Pet v3.2.1, commit `a325202`. Исходные рабочие деревья не редактировались.

Основное приложение уже использовало Tauri 2, WebView2, single-instance, bundled Node proxy и bootstrap Linux backend. Питомец также использовал Tauri 2. Совместимость позволила встроить его дополнительным локальным прозрачным окном `pet` того же native host. В пользовательском пакете один публичный entrypoint `Debugych.exe`, отдельного Pet EXE нет. Node в `resources/runtime` служит внутренним HTTP proxy.

Существующие React-страницы загружаются в iframe внутри доверенной локальной оболочки Tauri. HTTP frontend не получает privileged IPC. Минимальный bridge синхронизирует проект и точные маршруты результатов. Проверяются origin, source, идентификаторы, revision и session текущего iframe. Старые сообщения не могут вернуть предыдущий проект после смены подключения.

## Что сохранено и изменено

- Сохранены TypeScript-модули спрайтов, проигрыватель, реакции, Live/Demo, настройки размеров, движение и чат v3.2.1. Пять PNG атласов перенесены побайтно, без новых анимаций и переработки GLB.
- Общие подключение и проект хранятся в `connection.json`. Настройки питомца не дублируют URL и projectId на диске. История чата сохраняет прежние ограничения контекста.
- Старые настройки питомца копируются один раз, без изменения старого каталога.
- Верхняя панель управляет видимостью питомца. Его закрытие скрывает только дополнительное окно. Выход из главного окна завершает приложение.
- Ссылки на Bug Proof, diff и Fix & Verify адресуют конкретные сохранённые bug/run/fix внутри main. Внешний браузер для них не запускается.
- Центральный backend bootstrap остался прежним. Node, bootstrap и собственный WSL keepalive отслеживаются как дочерние процессы с Windows Job Objects. Общие контейнеры и WSL-сервисы не останавливаются.
- Меню локального подключения и будущего HTTPS backend сохранено. Адреса в питомце доступны для чтения; изменение подключения открывает настройки main.

## Исправленные проблемы интеграции

1. WebView2 мог вызвать IPC до регистрации Runtime. Это давало непостоянный native panic `state() called before manage()`. Автоматическое создание окон отключено. Сначала создаётся native-состояние, затем пустое окно питомца, его состояние и страница, затем главное окно. Проверены последующие реальные запуски.
2. Отсутствующие права локальных event listeners блокировали первую оболочку. Добавлена узкая capability для событий только двух bundled окон. Remote origin привилегии не получал.
3. Глобальное меню добавляло высоту прозрачному окну. Меню назначается только main.
4. Поздние ответы старого проекта могли конкурировать с новым выбором. Добавлены revision, iframe session, ready handshake, отмена чтений и защита pending selection. Устранён цикл сообщений при пустом проекте.
5. Восстановление через безусловный unminimize снимало maximized. Теперь unminimize вызывается только для действительно свёрнутого окна.
6. После неудачной смены API оставалась кнопка возврата к очищенному iframe. Старая навигация и кнопка сбрасываются при замене подключения.

## Реальное Windows-окружение

Проверялся release EXE на Windows с WebView2, WSL2 Ubuntu и уже работающим локальным API/gVisor. Управление настоящими окнами выполнено через computer-use skill, снимки и процессы сохранены в evidence.

- Двойной щелчок по ярлыку «Дебагыч Desktop 1.1» на рабочем столе запускает единое приложение.
- Верхний переключатель показывает и скрывает прозрачное окно. После перезапуска сохраняются видимость, настройки питомца и общий проект.
- Главное окно сворачивается, питомец продолжает читать backend и показывать результаты. «Открыть Дебагыч» восстанавливает main.
- Alt+F4 на питомце сохраняет работающие main и Node. Повторное включение переключателем возвращает питомца.
- Выбор в main проекта `d1ce559e-4c47-4a1f-9509-a944407d396d` передался питомцу. Возврат в питомце к `4552f6ba-cd41-48d4-a947-39e3b58314ac` передался main.
- Native перетаскивание изменило координаты питомца и сохранило anchor. Проверялись мониторы с разным DPI; unit-тесты дополнительно проверяют граничные размеры и восстановление anchor.
- Для проверки потери связи указан недоступный loopback `127.0.0.1:18091`. Main показал ошибку запуска, питомец - «Нет подключения». Старые результаты не объявлялись текущим успехом. После возврата на 8000 данные восстановились.
- Повторный запуск ярлыка при работающем приложении сохранил PID `2544`, единственный Node `43468` и собственный WSL keepalive `27896`. Второго backend не было.
- При полном выходе собственные GUI/Node/WSL процессы исчезли. Девять существующих Docker container ID до и после совпали, healthy-сервисы остались healthy.

Контрольный проект и результаты существовали до этой задачи. Показан исходный run `93bf09e7-c557-4575-82a4-9c92a30e2a6a` (7 PASS / 1 FAIL), Bug Proof `45a3e289-39c2-4bcd-b504-5e1ec62cb394`, fix `c41ceb12-55b9-4d85-87a3-332eba94717e`, сохранённая проверка `6f9c7776-5f17-4f66-bc59-e860f2af9ab5` (8 PASS / 0 FAIL, runsc). Ошибка: платеж при balance == amount отклонялся. Локальный ответ чата объяснил diff `>` -> `>=`. Это чтение результатов, не новый benchmark или новая AI-генерация. Патч к оригиналу не применялся.

## Поставка и ограничения

Portable-пакет: `outputs/debugych_desktop_1.1_windows.zip`. Запуск: распаковать весь каталог Debugych, затем Debugych.exe. Дополнительный скрипт создаёт ярлык, не перезаписывая ярлык другой копии. Исходники: `outputs/debugych_desktop_1.1_sources.zip`. Полная инструкция: `docs/windows-desktop.md`.

Видео `outputs/desktop11/debugych_desktop_1.1_demo.mp4`: 56 секунд, H.264, 1704x792, 15 fps, 840 кадров. Это монтаж двух реальных записей Windows-окон (40 + 16 секунд), без синтетических кадров. Показаны Bug Proof, переключение видимости питомца и сохранённая проверка Fix & Verify в runsc. Выполнено полное декодирование без ошибок и просмотр контрольных кадров через каждые 2 секунды. Записывалась только область приложения. Первые подготовительные дубли не входят в поставку.

После исправления порядка инициализации выполнены три успешных запуска GUI с PID 2544, 29712 и 31272. Отдельно проверены восстановление maximized переходом из питомца и полное закрытие итогового EXE. Ограничение инструмента UI-автоматизации при фокусировке развёрнутых Windows-окон не считается поведением продукта; итоговая запись выполнена в обычном оконном режиме.

Бюджет до/после: 5 оставшихся daily calls и $0.90264 резерва в обоих снимках. Дополнительных платных запросов не было. API подтвердил `applied=false` для контрольного исправления.

Пакет не подписан и не является MSI. Требуется WebView2 и заранее настроенные WSL2/Linux Docker/gVisor для локальных QA-запусков. Проверено переиспользование работающего backend; полный новый компьютер и холодная установка Linux-зависимостей не проверены. Bootstrap нового стека покрыт fixture, а не установкой на чистой Windows.

Реальный удалённый HTTPS сервер ещё не развёрнут, поэтому end-to-end удалённое подключение и серверная авторизация не подтверждены. Live AI чат сохранён, но внешние LLM-вызовы не выполнялись; browser AI consent проверен mock-транспортом без POST. Видео и скриншоты показывают сохранённые реальные результаты API.

Для интеграции достаточно проверить эту ветку и перенести её после согласования. Ветки 3D и параллельные UI/UX изменения не объединялись. Новый GLB, Three.js и анимации не добавлялись.
