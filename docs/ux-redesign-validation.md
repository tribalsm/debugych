## Что изменено

- Основная навигация: Главная, Мои проекты, Рабочая область. Внутри проекта: Обзор, Тесты, Ошибки, Отчёт. Breadcrumbs, project ID в URL, Назад и старые URL сохранены.
- Главная объясняет назначение продукта, предлагает создать проект или открыть существующее демо. Метрики выбранного проекта подписаны отдельно от каталога проектов.
- Мастер импорта: код, требования, настройки, запуск. Есть понятные ограничения файлов, частично успешная загрузка и ошибки. Настройки и технические ограничения раскрываются по запросу.
- Настоящая AI-генерация, подготовленное демо и повторный запуск сохранённых тестов различаются. Согласие содержит провайдера, модель, очищенный manifest и резерв расходов. Отказ не отправляет автономное задание.
- Активный AI-цикл показывает реальные стадии backend. Чтение кода, требований и генерация объединены, поскольку API сообщает их одной стадией. Пропущенным веткам доказательства и исправления не приписывается выполнение. История завершённого цикла раскрывается отдельно.
- Test Studio начинается с смысла проверки, ожидаемого результата и наблюдения. Сводка набора подписана как сводка, не как результат каждого assertion. Код и Gherkin открываются отдельно, техническая вкладка сохраняется по project ID. Редактирование, копирование, экспорт и строгая привязка валидации сохранены.
- Bug Lab показывает описание, ожидание, факт и воспроизведение. Traceback и diff закрыты по умолчанию. Критичность не выдумывается. Сравнение до/после опирается на API-записи исходника, исправления и регрессии.
- Проверка патча выполняется в копии. Условия применения сохранены без ослабления; отдельное подтверждение обязательно. Отказ от подтверждения оставляет патч неприменённым.
- Отчёт начинается со сводки. Аналитика, coverage, история и артефакты раскрываются по запросу, экспорт остаётся доступным. Выбирается последний фактический run/verify, а не любой исторический verify.
- Старый manual_review_required не переносится на успешный повторный цикл. Ответы предыдущего проекта отбрасываются после смены project ID, во время загрузки показывается skeleton.

### Новые UX-сценарии

1. Первый визит на пустом контрактном состоянии, описание продукта и создание проекта.
2. Рабочий вход в существующее демо без дублирования и AI-запросов.
3. Пошаговый импорт исходников и требований; отказ от передачи данных не создаёт задания.
4. Старые URL, project ID, перезагрузка и Назад.
5. Запоздалый ответ предыдущего проекта не загрязняет текущий экран.
6. Простой обзор, раскрытие кода/доказательства/diff, сравнение 13/1 и 14/0, отказ от применения.
7. Пропущенные ветви цикла и доказательства другого workflow не помечаются как выполненные.
8. Старый отказ не становится текущим предупреждением после успешного повтора.
9. Без API-ключа файлы загружаются, AI-запуск недоступен и объяснён.

### Экспертный usability walkthrough

Проведён сценарий первого использования на отдельном новом проекте: Главная -> создание -> пустой шаг кода -> загрузка calc.py -> шаг требований -> requirements.md -> рекомендованные настройки -> запуск -> просмотр согласия и отказ. Проверены недоступность продолжения без данных, доступность файлов, кнопка Назад, скрытые расширенные параметры и отсутствие POST /autonomous при отказе.

Второй walkthrough проходит на подготовленном демо с фактическими результатами Runner: исходный набор 13 passed / 1 failed -> воспроизводимое отклонение -> подготовленный diff -> изолированная проверка 14 passed / 0 failed -> отдельное подтверждение. Пользовательский показ оставляет патч неприменённым. Разрушительное для исходника подтверждение проверяется только на свежих специально созданных E2E-проектах.

Это экспертная и автоматизированная проверка, не испытание с реальными пользователями.

## Найденные проблемы и исправления в процессе

1. Повторение заголовка модуля в h2 и h3 делало поиск неоднозначным. Второе повторение стало текстом, семантический заголовок остался один.
2. E2E после скрытия артефактов должен раскрыть соответствующую секцию перед проверкой скриншотов. Проверки количества, размеров и скачивания сохранены.
3. Вспомогательный навигатор тестов пытался нажать скрытую мобильную кнопку, затем читать её атрибут на desktop. Добавлена проверка видимости и aria-expanded. Второй предварительный dev-прогон остановлен после диагностики этой ошибки вспомогательного кода.
4. API E2E сначала прошёл assertions, но не смог сохранить отчёт из-за отсутствующего локального work/. Каталог создан, сценарий повторён. Исходники backend не менялись.
5. Старое предупреждение manual review и предпочтение любого verify текущему run давали устаревшую картину. Добавлены выбор последнего задания и регрессионные сценарии.
6. После завершения подробная карточка хода работы оттесняла результат. Завершённая история свёрнута, важный результат и следующий шаг подняты выше. Импорт без результатов сразу показывает мастер.

Первый предварительный dev-прогон: 14 passed, 3 unexpected. JSON и traces сохранены в outputs/uiux-checks/. Ошибки не удалены из истории и не учитываются как успешный результат.

## Оставшиеся ограничения

- API не предоставляет отмену, отдельные стадии извлечения требований, обоснованную критичность или глобальную историю результатов всех проектов. Неработающие кнопки не добавлялись.
- AI-модуль описывает тестовый модуль; внутри него может быть несколько assertions. Семантическая связь каждого кейса с несколькими требованиями не выводится из общего статуса и не выдумывается.
- Импорт определяет наличие документа по расширению. Достаточность требований проверяет AI workflow, а не наличие файла само по себе.
- Мастер сохраняет файлы на сервере, но номер шага после перезагрузки не сохраняется. Можно перейти к нужному шагу. Техническая вкладка теста сохраняется отдельно для проекта.
- Большой каталог фильтруется в браузере. Виртуализация и серверная пагинация не добавлены. Для одинаковых имён проектов остаётся риск неоднозначного выбора по названию.
- Отмена применения закрывает системное подтверждение и сохраняет неприменённый патч; отдельного постоянного статуса отказа API не предоставляет.
- Полная корректность приложения не доказывается прохождением набора или высоким покрытием. Процент прохождения не называется качеством ПО.
- Новые paid/live проверки GPT-6 Luna не выполнялись. Здесь проверяется UI-интеграция, а не способность модели находить новые ошибки.
- 3D не подключён. [Контракт MascotSlot](uiux-mascot-contract.md) сохранён: восемь состояний, children renderer, reducedMotion. На узких экранах полная декоративная область скрывается; future renderer должен избегать ненужной загрузки невидимого ресурса.

```sh
  -f docker-compose.yml -f compose.test.yml -f compose.redesign.yml build web

  -f docker-compose.yml -f compose.test.yml -f compose.redesign.yml \
```

Нужны уже подготовленные образы debugych-uiux-api:local, debugych-uiux-runner:local, debugych-uiux-supervisor:local и существующие sandbox-образы. Это окружение проверки, не конфигурация реального LLM-провайдера. Не выполнять общий rebuild или очистку Docker-хоста.


Для dev-предпросмотра использовать свободный порт и API_TARGET=http://127.0.0.1:8012. Финальный показ использует production 8082.
