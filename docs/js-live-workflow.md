# JS/TS live workflow: gpt-6-luna

> Протокол предыдущего этапа. Новая автономная серия и её частичный результат: [autonomous-ai-validation.md](autonomous-ai-validation.md).

20 октября 2026, Asia/Tomsk. Настоящий провайдер `https://triklz27.ru/v1`, модель пользователя `gpt-6-luna`. Контрактные результаты указаны отдельно.

**Проверенный результат:** неизменённые LLM-тесты обнаружили оба контрольных JS-дефекта. Bug Proof, настоящий AI-diff и Fix & Verify выполнены в gVisor. После патча проходят 6/6 сгенерированных кейсов и 4/4 приватных oracle. Исходники и тесты не изменены, патч не применён.

**Ограничение автономности:** LLM-reviewer ошибочно отклонил корректный черновик. Его проверил и явно принял агент по поручению пользователя, до первого исполнения, без изменения кода тестов. Это результат реальной LLM с отдельной проверкой черновика, а не успешный полностью автономный quality gate. Исправленная инструкция reviewer в этой бюджетной серии повторно на настоящей модели не проверялась.

## Изменения

- Для JS/TS при `LLM_TEST_REVIEW=1` модель составляет acceptance contract одновременно с извлечением требований. На этом этапе передаются только документы. Конкретные действия и постусловия получаются до просмотра реализации; ссылки должны покрывать ровно известные требования. Отдельный дополнительный API-запрос больше не нужен.
- Генерация использует этот контракт, требования и исходники для построения исполняемых тестов. Инструкция требует правильной параметризации, уникальных названий, точных селекторов и ожидаемых значений из документа. Для небольших наборов рекомендуются явные кейсы.
- Reviewer получает требования, контракт и тесты, без реализации, результатов выполнения и oracle. Его задача уточнена: конкретные противоречия и ошибки исполнения; дополнительные пожелания к покрытию не должны превращаться в придуманные требования. Подсказки не содержат приватных дефектов или конкретных чисел контрольного проекта.
- Валидированные отклонённые черновики сохраняются в `generation_review` записи анализа. Это данные проекта, не исполняемые test-cases и не общий журнал. Privacy-фильтр применяется повторно. AI-логи по-прежнему содержат только безопасные метаданные.
- `POST /api/projects/{id}/accept-ai-draft` позволяет явно принять сохранённый черновик после независимой проверки. Требуются `confirm`, точные ID/index/SHA черновика, SHA состояния проекта, замечание reviewer и `reviewer_kind=human|agent`. Сервер повторно проверяет структуру, связи и framework; отвергает изменившийся проект, активное задание, существующий план, чужой анализ и повторное принятие. Клиент не передаёт новый код. Исходный неуспешный анализ сохраняется; тесты имеют origin `llm-reviewed-draft` и provenance проверки. Новый маршрут пока доступен через API.
- Контекст исправления сокращён: полные разрешённые исходники и требования, SHA тестов, имена падений и явно обозначенные выдержки assertions без повторяющегося Playwright call log. Полные тесты и traceback сохраняются на сервере; verify исполняет их неизменёнными. Проверки source SHA, допустимых файлов и минимального diff сохранены.
- Benchmark поддерживает `--project react_booking` для ограниченного запуска одного синтетического проекта.

## Фактическая live-серия

| Попытка | Результат |
|---|---|
| Отдельное doc-only планирование | 6 запросов. Первая версия контракта отклонена за связи требований; повтор принят. Reviewer отклонил тесты, коррекция остановлена общим дедлайном 160 s. Успешного набора нет. |
| Совмещённые extraction + contract | 5 запросов. Генерация и одна коррекция структурно корректны; reviewer оба раза отклонил черновик. Анализ остался failed. |
| Независимая проверка второго черновика | Без LLM-запросов и без изменения тестов. Явное принятие с reviewer_kind=agent, затем настоящий runsc: 4 passed / 2 failed / 0 errors. |
| Bug Proof | Полный replay: те же 2 падения, те же test/case identities и образ. |
| Первая заявка на diff | До отправки HTTP отклонена общим бюджетом. Никакого списания reservation или скрытого дополнительного LLM-запроса. |
| Компактный запрос исправления | 1 настоящий запрос, лимит ответа 1000 токенов. Получен минимальный diff на две строки. Verify: 6 passed / 0 failed. |

Проверенные ложные замечания reviewer: требование перечислить все целые значения диапазона; утверждение, что уменьшение остатка не меняет состояние; отклонение точного `p[role="status"]` из-за отсутствия DOM-ролей в бизнес-документе. Он также принял иллюстративные значения acceptance contract за дополнительные требования. Эти замечания не использовались для изменения ожиданий после исполнения. Оба отклонённых черновика второго анализа сохранены, включая замечания.

В выбранном черновике R1 последовательно проверяет уменьшение остатка и бронирование всего оставшегося количества; R2 — 0, отрицательное, дробное и превышающее остаток значения с неизменным состоянием; R3 — восстановление всех документированных полей после изменения состояния. Сопоставление сделано по публичным требованиям и DOM, без приватных oracle.

## Независимый benchmark

Приватные тесты, исправления и варианты дефектов находятся только у evaluator. Генератор, reviewer и patch model их не получают. После генерации выполнены 9 дополнительных изолированных контрольных запусков; время evaluator — 109.047 s.

| Метрика JS/TS | Факт |
|---|---:|
| Обнаруженные известные дефекты | 2/2: TS-CAPACITY, TS-RESET |
| Пропущенные / неоцениваемые | 0 / 0 |
| Ложные падения на исправленном эталоне | 0 |
| Исполнимые модули / кейсы | 3/3 / 6/6 |
| Требования с выполненными assertions | 3/3 |
| Воспроизведение Bug Proof | 2/2 падений |
| Сгенерированные / проверенные патчи | 1 / 1 |
| Приватные oracle на AI-кандидате | 4 passed / 0 failed |
| Регрессии в сохранённом наборе | 0 |
| Дополнительная ручная мутация | 1/1 уничтожена |
| Измеренное покрытие собранного JS | строки 13/13; ветви 5/5 |

Это маленький уже использовавшийся корпус, не новый holdout и не оценка универсального обнаружения ошибок. Полное покрытие скомпилированного JS не доказывает корректность требований или полноту набора. Проверена одна дополнительная мутация, не широкое mutation testing. Предыдущий Python live-результат 2/2 не выдаётся за новый запуск этой серии или за автономные 4/4.

Агент/evaluator знаком с контрольным корпусом из предыдущего этапа; его отдельная проверка не является слепой человеческой оценкой. Ожидания проверялись по публичной спецификации, тестовый код LLM не менялся. Приватные oracle и эталонный патч не передавались генератору или patch model.

## Бюджет и статистика

Предел серии реально обеспечивался атомарным суточным admission budget: от исходных 31 запроса / $5.54034 до максимум 43 / $7.54034. После серии исходные пользовательские суточные лимиты и лимит ответа восстановлены. Key/base URL/model не менялись.

- Новые provider POST: **12**, предел 12. Из них 10 структурно допустимых ответов и 2 неуспешных: неверные связи контракта и таймаут на коррекции. Структурный успех не означает успешный набор или одобрение reviewer.
- Автоматически принятые новые наборы: **0**; явно проверенные агентом неизменённые наборы: **1**.
- Токены по usage у 11 ответов: input **16859**, output **7250**, всего **24109**. Для одного таймаута usage неизвестен.
- Новый консервативный reservation: **$1.99111**, предел $2. Это не счёт провайдера; фактическая денежная стоимость неизвестна.
- Суммарное время новых LLM-попыток: **329.687 s**. Во всех ответах с model указан `gpt-6-luna`.
- За всю сохранённую историю live: 43 POST, 28 структурных успехов / 15 ошибок. Новая серия не скрывает предыдущие неудачи.

## Регрессия и безопасность

- Backend: **150 passed**, одно предупреждение upstream AnyIO.
- Новый API E2E отклонённый draft → явная проверка → gVisor → Bug Proof → diff → verify → запрет apply без подтверждения: **passed**. Транспорт в нём явно контрактный, выполнение настоящее.
- Браузерные E2E: **9 passed (1.8 min)**, включая ожидаемое контрольное падение доверенного Shop. Транспорт AI в этих сценариях контрактный; gVisor и браузер исполняются по-настоящему.
- Compose / PostgreSQL / Redis / Celery и оба runsc-профиля работали. `docker compose config --quiet` прошёл. В конце восстановлен обычный Compose с настоящим провайдером, stub удалён, health=ok и оба gVisor-профиля доступны. Образы runner не пересобирались; live replay и verify закреплены за одним образом Playwright.
- Не менялись ограничения runner: network=none, read-only rootfs, non-root, запрет capabilities, фиксированные команды/образы и лимиты. LLM работает в доверенном backend; ключ в песочницу не передаётся.
- Unconfirmed apply возвращает **409**. Архив исходников и байты тестов до/после verify одинаковы. Никакой live-патч не применялся.

## Воспроизведение

Для нового платного запуска после просмотра синтетических файлов:

```sh
python tests/compose/benchmark.py --allow-external --project react_booking --output work/js-benchmark.json
```

Команда отправляет только `evaluation/projects/react_booking`; она не подтверждает патч и останавливается перед отдельной проверкой ожиданий. Принятие draft не выполняет внешний запрос: получите `generation_review` через `GET /api/runs/{analysis_id}`, проверьте неизменённый план по документу и передайте перечисленные выше поля в `accept-ai-draft`. Наличие маршрута не означает разрешение молча игнорировать reviewer.

Новый сквозной контрактный тест:

```sh
docker compose -f docker-compose.yml -f compose.test.yml -f tests/compose/review.test.yml up --no-build -d --wait
python tests/compose/draft_review_smoke.py
# Для обычных browser E2E выключите специальный negative-review fixture:
docker compose -f docker-compose.yml -f compose.test.yml up --no-build -d --wait
# После тестов верните настоящий провайдер:
docker compose up --no-build -d --remove-orphans --wait
```

Доказательства: `live-js-benchmark.json`, `live-js-fix-verify.json`, `live-js-budget.json`, `live-js-reviewed-drafts.json`, `draft-review-e2e.json`, `js-compose-final.json`. `live-js-artifacts.zip` содержит 24 артефакта original/proof/candidate (PNG и JSON), исходные неизменённые тесты, AI-diff и manifest с проверенными SHA256. Предыдущие отчёты сохранены как история, не смешанная с результатами новой серии.
