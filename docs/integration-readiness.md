## Найденная проблема подготовки E2E

Первый завершённый прогон на новой базе дал 27/28: `redesign-wide.spec.ts` искал существующий демопроект через GET `/api/projects`, хотя ранние сценарии создавали только загруженные проекты. Историческое непустое окружение скрывало эту зависимость от порядка и состояния базы. Тест теперь сам вызывает POST `/api/demo` и проверяет успешный ответ с `demo=true`. Все проверки шести экранов, заголовков и отсутствия переполнения при 1920/2560 сохранены, таймауты не менялись. Отдельный запуск исправленного теста прошёл. Неуспешный прогон сохранён отдельно.

## Воспроизводимый E2E-стенд

Следующий Windows-прогон выявил отдельный сбой хоста: trace фиксирует `Test timeout of 60000ms exceeded while setting up page`, после `Create context` и зависшего `Create page`. Тело теста ещё не выполнялось. Прогон прерван, trace и журнал сохранены. Диагностический запуск bundled Chromium завершился `spawn UNKNOWN`, а проверка 40 последовательных контекстов установленного Chrome остановилась на собственном дедлайне 30 секунд. Это не объявлено исправленным дефектом приложения и не скрыто retries.

Для проверки интеграции добавлен `infra/run-integration-e2e.ps1`. Он собирает собственный доверенный UI E2E-контейнер из уже проверенного Linux runtime с Playwright **1.64.1**, копирует локальные lockfile-зависимости axe/lucide и запускает существующие 28 сценариев. Windows npm-окружение содержит Playwright **1.55.1**; оно не выдаётся за версию успешного Linux-прогона. `apps/web/playwright.config.ts` не изменён. Assertions, workers=1, retries=0 и существующие таймауты сохранены.

```powershell
# Из корня этой рабочей копии после npm ci и запуска debugych-integration:
./infra/run-integration-e2e.ps1
```

Контейнер подключается только к собственной backend-сети и читает тесты, frontend source и fixtures через read-only mounts. Записывает только собственные outputs. Работает non-root, с read-only root, без capabilities/socket/секретов, с ограничениями 1 CPU / 1 GiB / 256 PID. Он проверяет доверенный интерфейс; загруженные проекты исполняются отдельным gVisor Runner с прежним `network_mode: none`. Изоляция этих job-контейнеров не менялась.

Первый Linux-прогон дал 27/28 из-за `EPERM` в copyfile при записи trace на Windows bind mount; HTML reporter также не смог скопировать CSS. Исправлен только filesystem тестового стенда: теперь все runtime-артефакты пишутся в отдельный Linux volume, после завершения экспортируются через `docker cp`. Volume имеет уникальное имя и сохраняется как дополнительное локальное доказательство, глобальная очистка Docker не выполняется. Финальный полный прогон прошёл 28/28.

## Оставшиеся ограничения

- Прямой Windows E2E-хост нестабилен при создании страниц. Его проблема не объявлена устранённой; воспроизводимая проверка интеграции выполняется через отдельный Linux E2E-стенд.
- Для предпросмотра нужен активный WSL-сеанс. Глобальные настройки WSL и daemon не менялись; скрытый keepalive остаётся активным.
- Полная сборка с повторной загрузкой всех базовых образов не завершалась; проверена сборка текущего кода на сохранённых зависимостях и production assets.
- Live GPT-6 Luna повторно не проверялась. Результаты контрактного провайдера не подтверждают новое live-качество генерации.
- Конкретная GLB-модель, лупа, GPU-рендеринг и анимации не интегрированы и не проверены.

Неустранённых функциональных регрессий в завершённом Linux-наборе не обнаружено. Это готовность UI и технического контракта к следующему этапу, а не подтверждение уже работающей 3D-интеграции или новой live LLM-проверки.

## AI и безопасность

Предпросмотр использует **явный локальный контрактный провайдер** `http://llm-stub:8101/v1`. Ключ настоящего провайдера и исходный `.env` не загружались. Извлечение требований, генерация, валидация, очередь Celery, сохранение в PostgreSQL, выполнение, Bug Proof и Fix & Verify проверяются через действующий backend. Результаты исполнения и артефакты фактические; ответы генерации подготовлены локальным провайдером и не являются новой проверкой GPT-6 Luna.

Проверка настоящей LLM в этой интеграции **НЕ ВЫПОЛНЯЛАСЬ**, поскольку платные запросы запрещены. Исторические live-benchmark не выдаются за результаты этой проверки.

Лимиты gVisor, запрет сети, non-root UID, read-only root, отсутствие capabilities, `no-new-privileges`, запрет host mounts/socket/секретов в job-контейнере сохранены. Патчи применяются только после серверной проверки и отдельного подтверждения. E2E проверяет применение исключительно на созданных им одноразовых проектах. Демопроект предпросмотра остаётся с проверенным, но не применённым патчем.

Точка подключения сохранена: `apps/web/src/MascotSlot.tsx`, props `state`, `compact`, `reducedMotion`, `children`. Поддерживаются `idle`, `analyzing`, `generating`, `testing`, `bug_found`, `fixing`, `success`, `error`. Полный слот находится на Dashboard, остальные страницы используют компактный текстовый статус. Three.js, GLB, лупа, риг и анимации не переносились. Интерфейс завершённо работает без renderer. Будущий renderer должен учитывать reduced motion, не перехватывать прокрутку, иметь Error Boundary/fallback и освобождать WebGL-ресурсы. Фактическая работа модели и аксессуаров здесь не проверялась.

После сохранения результата 3D-процесса создать отдельную согласованную ветку для подключения renderer. Его текущая ветка уже базируется на `d019065`, поэтому повторно переносить UI- и Runner-commits не нужно. Не заменять весь `apps/web` и не ослаблять обработчики согласия или серверные проверки применения. Слияние с `main` требует отдельного разрешения пользователя.
