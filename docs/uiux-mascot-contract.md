# UI-контракт будущего маскота

Этот этап меняет только UI. Модель, GLB, риг, анимации и Three.js здесь не создаются и не подключаются. Файлы 3D-процесса не переносятся из его незавершённого дерева.

## Точка подключения

`apps/web/src/MascotSlot.tsx` экспортирует `MascotSlot`, `AgentState` и чистую функцию `agentState`. Dashboard использует полный слот. Остальные страницы используют компактную панель статуса без 3D-области.

```tsx
<MascotSlot state={state} reducedMotion={reducedMotion}>
  {/* Будущий renderer DebugychMascot, переданный владельцем 3D-интеграции */}
</MascotSlot>
```

Props:

| Поле | Контракт |
| --- | --- |
| `state` | `idle`, `analyzing`, `generating`, `testing`, `bug_found`, `fixing`, `success`, `error` |
| `compact` | Только текстовый статус. Не монтировать renderer на каждой странице |
| `reducedMotion` | Пользовательская настройка или системный prefers-reduced-motion. Renderer обязан её учитывать |
| `children` | Необязательный renderer. Без него остаётся законченная панель с библиотечной иконкой ShieldCheck, без альтернативного персонажа |

Полная область адаптивна: ширина контейнера, aspect-ratio 2/1, минимальная высота 140 px; на узком экране высота сокращается. Renderer должен занимать область без изменения размеров страницы, оставлять текстовый статус и не перехватывать прокрутку.

## Семантика

- Стадии приходят из jobs API. UI не придумывает проценты или длительность выполнения.
- Passed обычного теста не означает `success` всего продукта.
- `bug_found` требует confirmed. Reproduced не подтверждает дефект.
- `success` связан с проверенным исправлением, но не означает его применение и не доказывает полную корректность.
- При manual_review_required основное сообщение об остановке остаётся видимым отдельно. Панель не объявляет успех.
- Ошибка задания не является доказательством дефекта приложения.

## Ответственность renderer

Загрузка ассетов и обработка отказов, Error Boundary, fallback, освобождение WebGL/текстур/геометрии и политика анимаций принадлежат 3D-интеграции. Ошибка renderer не должна скрывать API-интерфейс. Декоративная модель должна быть исключена из accessibility tree; доступный текстовый статус уже есть в слоте.

Не менять обработчики API, согласие на отправку кода провайдеру или отдельное подтверждение применения исправлений. Не загружать GLB, пока renderer не подключён. UI этой ветки не делает GLB-запросов и не содержит зависимостей Three.js.

Подключать renderer следует в отдельной интеграционной ветке после сохранения результатов обоих процессов. Не заменять весь `apps/web` файлами одного из рабочих деревьев.
