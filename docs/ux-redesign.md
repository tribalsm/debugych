## Архитектура

Основная навигация: Главная, Мои проекты, Рабочая область. Контекстные вкладки проекта: Обзор, Тесты, Ошибки, Отчёт. URL /#/workspace/{overview,tests,bugs,report}?project=ID сохраняет идентификатор проекта и работает с Назад. Старые /#/test-studio, /#/bug-lab, /#/reports продолжают работать.

Путь: Главная -> создать проект -> добавить код -> требования -> рекомендованные настройки -> подтвердить отправку данных и резерв расходов -> автономный запуск backend -> результаты -> доказательство -> предложение -> проверка копии -> отдельное подтверждение применения.

Демо использует существующий демопроект, если он есть. Его подготовленные план и патч явно отличаются от настоящей генерации и повторного запуска сохранённых тестов. Результаты не генерируются в браузере.

## Прогресс и границы API

Backend автономного цикла сообщает generation, persist_validated_plan, execution, bug_proof, patch_generation, fix_verification, report. Код, требования, план и генерация объединены в одну реальную стадию. Отдельные проценты и длительности этих подэтапов не придумываются. Ветки доказательства и исправления могут не потребоваться. API отмены нет, кнопка отмены не создаётся.

Простой режим показывает смысл и результат. Код, Gherkin, traceback, diff, аналитика и артефакты доступны по запросу. Нельзя вывести точный результат каждого assertion из общего статуса модуля: показывается честная сводка набора, отдельные кейсы находятся в результатах.

## Сохранённые ограничения

AI Engine, Runner, политика безопасности, Bug Proof, Fix & Verify, миграции и 3D не редактируются. Модель и бюджет настраиваются сервером. Платные вызовы для UI-проверки запрещены. API не предоставляет обоснованную критичность дефекта, глобальную агрегированную историю всех проектов, отмену задания или подробный прогресс извлечения требований. Эти возможности требуют отдельных backend-доработок.

## Текущий статус и история

Предупреждение manual_review_required относится к последнему корневому заданию. Старый отказ сохраняется в истории, но не становится текущим состоянием после успешной повторной проверки. Отчёт выбирает последний фактический run/verify по хронологии, а не любой существующий verify. Смена проекта очищает контекст немедленно, устаревшие ответы проверяются по project ID. Выбранная техническая вкладка сохраняется отдельно для каждого проекта.

Маскот на Главной получает состояние выбранного проекта. Во время задания видимое сообщение содержит название проекта и понятное действие; техническая стадия раскрывается отдельно. Подключение renderer остаётся через MascotSlot, контракт восьми состояний не меняется. Три самостоятельные стадии чтения кода, извлечения требований и планирования не анимируются как будто сервер сообщает их отдельно.
