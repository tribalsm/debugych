## Изоляция и авторизация

- Внешний nginx слушает 9443. API доступен только на 127.0.0.1:18080. PostgreSQL, Redis и Docker API наружу не опубликованы.
- Все API-маршруты, документация и будущие WebSocket требуют Bearer-токен. Исключение: минимальный `/healthz`. Отсутствующий или неверный токен даёт 401; некорректная серверная конфигурация закрывает доступ.
- Это одно доверенное пространство одного владельца, не многопользовательский SaaS с разграничением проектов.
- На сервере хранится SHA-256 токена, отдельным read-only bind mount. Ротация сохраняет inode: иначе Docker продолжал бы читать прежний файл. Реальная ротация без перезапуска API проверена: старый токен 401, новый 200.
- Windows хранит токен в Credential Manager с привязкой к HTTPS origin. Токен не возвращается JavaScript. В собственный Node-прокси он передаётся через private stdin, не через argv или переменные окружения. Внешние Cookie/Authorization от браузера не пересылаются.
- Proxy проверяет Host, Origin/Fetch Metadata, не отключает TLS-проверку и не следует внешним перенаправлениям.
- Ключ LLM находится в `/etc/debugych/production.env`, а не в frontend, образе или песочнице.
- Supervisor сохраняет единоличный доступ к Docker socket. Пользовательские задания выполняются в runsc: без сети, read-only, non-root, с ограничениями CPU, памяти, PID, времени и tmpfs. Параллелизм сервера 1.
- Логи nginx для этого API отключены. Не следует включать дамп заголовков или тела запросов в диагностике.

## Эксплуатация

Текущий deployment: `/opt/debugych/releases/server10-3bba37d`, Compose project `debugych-server`. Секреты находятся отдельно в `/etc/debugych`. Каталог релиза содержит экспорт исходников базового commit 3bba37d и последующие исправления операционных скриптов. `SOURCE_COMMIT` обозначает базовый экспорт, а не побайтовую идентичность финальной ветке.

В каталоге релиза:

```sh
sh scripts/serverctl.sh validate
sh scripts/serverctl.sh health
sh scripts/serverctl.sh backup /root/debugych-backups/UNIQUE-NAME
sh scripts/server-restore-test.sh /root/debugych-backups/UNIQUE-NAME
```

Backup кратковременно останавливает только api/worker этого Compose project, затем запускает их. Не вызывайте его для намеренно остановленного стека: текущая команда снова запустит api/worker. Включает PostgreSQL dump, файлы проектов, контрольные суммы и базовый commit. Секреты не включает, храните их резервную копию отдельно в защищённом месте. Проверенный VPS backup: `/root/debugych-backups/20261028-initial`. Restore-test создаёт отдельные временные БД и volumes, не заменяет рабочие данные.

Для обновления: создать отдельный каталог релиза, проверить конфигурацию, сделать backup, собрать образы и запускать только project debugych-server. Сначала проверить совместимость миграций и восстановление. Откат образа после несовместимой миграции без восстановления БД не является безопасным rollback. Не используйте Docker prune, restart daemon или команды отключения WSL/VPN.

Ротация ключа на VPS:

```sh
python3 scripts/server-auth.py --hashes /etc/debugych/owner-hashes --client-out /etc/debugych/owner-bootstrap.token --api-uid 10001
```

Команда не печатает токен. Новый токен передавайте владельцу по защищённому каналу и сохраняйте через поле подключения приложения. Старый сразу перестаёт действовать. Bootstrap token пока оставлен в root-only файле для оператора; после завершения безопасной передачи его следует удалить. Не вставляйте токен в URL, командную строку, отчёт или чат.

В Windows: «Подключение», режим Remote, указанный HTTPS URL, серверный токен. VPN route оставить пустым. Новая установка использует этот адрес по умолчанию; существующая пользовательская конфигурация сохраняется. При смене origin ключ нужно сохранить для нового origin. Главное окно и pet используют один backend и проект. Открытие доказательства идёт через главное окно.

## Ограничения и непроверенное

- Новая платная генерация, полный live AI E2E и нагрузочное тестирование не выполнялись.
- Финальная визуальная проверка двух native окон, сворачивания, перехода к Bug Proof и видеозапись не завершены: пользователь работал в другом полноэкранном приложении, фокус не перехватывался. Проверены регистрация двух окон и настоящий transport, а не весь GUI-сценарий.
- Полная перезагрузка VPS не выполнялась, чтобы не прерывать чужие сервисы. Docker включён, контейнеры имеют restart policy. Шаблон systemd unit находится в исходниках, но отдельный unit не установлен.
- Сертификат не отменяет необходимость токена. Серверный web UI не является публичной страницей входа: desktop выполняет аутентификацию через собственный proxy.
- Windows-сборка не подписана коммерческим сертификатом. Установка новой версии на рабочий профиль и финальный native smoke после упаковки ещё не проверены.
- VPS имеет 2 CPU и около 4 GB RAM без swap. Параллелизм намеренно ограничен; состояние диска и backup необходимо мониторить.
- Имя nip.io зависит от стороннего DNS и меняется при смене IP. Для постоянного короткого адреса нужен собственный домен.
- Существующие VPN, Xray и nginx-сайты не заменялись. Docker ip-forward-no-drop сохраняет forwarding. Выполнялся только graceful reload nginx.

Основания настройки: [Docker Debian](https://docs.docker.com/engine/install/debian/), [Docker firewall](https://docs.docker.com/engine/network/packet-filtering-firewalls/), [gVisor install](https://gvisor.dev/docs/user_guide/install/), [gVisor production](https://gvisor.dev/docs/user_guide/production/).
