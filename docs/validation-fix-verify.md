# Проверка Bug Proof и Fix & Verify

Дата: 19 октября 2026. Проверено локально на Windows + WSL Ubuntu, Docker Compose, PostgreSQL, Redis, Celery и обязательном gVisor (`runsc`).

## Результаты

- `python -m pytest -q`: **65 passed**, 7.17 с. Единственное предупреждение — deprecated alias AnyIO внутри Starlette TestClient.
- `COMPOSE_CONTRACT_TEST=1 PLAYWRIGHT_BASE_URL=http://127.0.0.1:8080 npm run test:e2e`: **7 passed**, 27.7 с. Один тест намеренно объявлен expected failure: показывает исходный дефект доверенного Shop. В итоговые 7 входит его корректное ожидаемое падение.
- `python tests/compose/fix_verify_smoke.py`: полный API-путь с реальными очередью, БД и gVisor; исходный прогон **2 passed / 1 failed**, целевой модуль после патча **1 passed / 0 failed**, полный план **3 passed / 0 failed**. Исходный снимок также повторно проверяется при Bug Proof и перед проверкой кандидата. Все запуски проверки используют один image ID.
- `tests/compose/sandbox_probe.py` внутри supervisor: пройдены проверки токена, запрета произвольных Docker-параметров и несовпадающего image ID, UID, отсутствия секретов и host mounts, readonly root, capabilities, отсутствия сети, NPROC, памяти, таймаута и удаления контейнеров. Превышение памяти реально завершилось OOM / exit 137; спящий тест остановлен по 30-секундному таймауту.
- `docker compose -f docker-compose.yml -f compose.test.yml up -d --wait --wait-timeout 60`: сервисы healthy, init завершился с кодом 0.
- Возврат к обычному Compose: `ai_available=false`, `ai_provider_mode=live`, `sandbox_available=true`. Production frontend собран заново. После принудительного пересоздания API запрос через Nginx на `/api/health` успешен; Nginx теперь обновляет адрес upstream через Docker DNS. Просмотр проверенного diff и трёх результатов в браузере также проверен без LLM-ключа (`fix-verify.png`).

## Что проверяют сквозные сценарии

Браузер проходит загрузку Python-проекта, AI-анализ, запуск, ручной review требования, повторное доказательство, предложение diff, три проверки в gVisor и отдельное подтверждение применения. Отмена диалога не применяет патч. После подтверждения доступен ZIP, повторный запуск проходит полностью.

API-сценарий дополнительно проверяет отказы при неподтверждённом ожидании, неверном SHA теста, предложении без Confirmed, применении без успешной проверки, неправильном SHA патча и изменении проекта после проверки. Источник до подтверждения побайтно совпадает с исходным ZIP. Патч-ловушка исправляет целевой тест, но ломает ранее проходивший регрессионный кейс: проверка возвращает `verified=false`, применение запрещено. Новое предложение сохраняется отдельной версией. Код тестов не меняется; повтор того же подтверждения применения идемпотентен.

Unit/integration-набор проверяет политику путей, запрет изменения тестов и создания файлов, AST, no-op, исходные SHA, canonical diff, неоднозначные кейсы, ошибки/пропуски, сохранение нескольких файлов одной транзакцией, откат при ошибке записи и сохранность уже зафиксированных blob при потере подтверждения COMMIT.

## Границы результата

Внешний LLM заменялся **явно включённым контрактным провайдером** из `compose.test.yml`. Он выдаёт подготовленные ответы анализа и структурированного патча. Запуски Python, падения, регрессии и применение реальны. Проверка живого LLM не проводилась: ключ не предоставлен. Обычный Compose запускается без тестового провайдера; для генерации нужен пользовательский ключ.

Confirmed означает подтверждённое человеком ожидание плюс повторяемый сбой; это не независимое доказательство корректности требования. Регрессия охватывает весь сохранённый pytest-план Test Studio. Неподготовленные зависимости и произвольные репозиторные команды не запускаются. Отчёт исполняемого недоверенного проекта не является криптографически достоверным доказательством или гарантией полной корректности программы. Эти ограничения показаны в интерфейсе и описаны в `fix-and-verify.md`.

Подготовлен дополнительный синтетический пример с проверенным, но **не применённым** патчем; его ID — в `review-example.json` в пакете результатов. Пользовательские проекты этим примером не затрагиваются.

Исходный код, конфигурация CI и воспроизводимые команды входят в архив. Удалённый CI в этой сессии не запускался.
