# Дебагыч AI Companion 1.0

Реализация находится в отдельной ветке `release/ai-companion-1`, созданной от Redesign 2.0 integration `b9ac4a26d709f0ccd5634efdf6cdb362fdbeb903`. Merge не выполнен. Backend, AI Engine, gVisor и алгоритмы Bug Proof / Fix & Verify не изменены.

## Предпросмотр

- Приложение: http://127.0.0.1:5190/
- Отдельная ручная демонстрация: http://127.0.0.1:5190/#/companion-demo
- Посадка из предыдущего этапа: http://127.0.0.1:8790/

Свой frontend на 5190 использует существующий Vite proxy на локальный API 8015. API и trusted demo Runner 8095 запускаются из этой ветки без изменений исходников. Собственные SQLite и DATA_DIR находятся в `outputs/companion/`. Чужие контейнеры и процессы не перезапускались. Для preview очищены LLM_API_KEY и OPENAI_API_KEY, SANDBOX_ENABLED=0. Health честно сообщает `trusted-demo-only`; live AI и gVisor этим показом не проверялись.

## Backend-события

Используется прежний polling приложения, без новых серверных endpoint, таймеров результатов, SSE и параллельного pipeline. Источники: GET /projects, /projects/{id}/runs, /requirements, /test-cases, /fixes и /bugs?project_id=.

| Состояние | Основание |
| --- | --- |
| idle | Нет активной задачи, план/результат готов или нужен ручной review |
| analyzing | Подтверждённая активная задача анализа |
| generating | status generating или стадия генерации |
| testing | run, confirm_proof, execution, bug_proof |
| bug_found | Только confirmed / fix_verified, связанный с текущим workflow |
| fixing | propose_fix / verify, patch_generation / fix_verification |
| success | Совпали проект, баг, патч, verification_id и patch_sha256 (если предоставлен); завершён verify, fix.verified=true, original_fixed=true, regressions_absent=true |
| error | Ошибка задания / инфраструктуры / получения актуального снимка |

Адаптер фильтрует project_id, выбирает последний root workflow и его потомков. Старое подтверждение другого патча или запуска не даёт success. Успешное выполнение тестов само по себе не означает исправление. Контекст сбрасывается при смене проекта; ответы старого polling и ошибок старого action защищены selectedRef. Сетевое состояние Companion очищается после успешного обновления. Очень короткие стадии могут не попасть в интервал существующего polling 1.5 с, промежуточные состояния по таймеру не выдумываются.

## Панель и реальные действия

`DebugychCompanion` использует существующий `MascotSlot`. Compact содержит сцену 220 px, Expanded сцену 280 px и пояснения, Hidden оставляет кнопку восстановления. Настройки режима, реплик и движения сохраняются локально. Широкий экран получает отдельную колонку, узкий экран блок в потоке, мобильный компактный режим кнопку без Canvas. Панель не перекрывает код, diff и управление Bug Lab.

Нажатие персонажа или заголовка открывает панель. Локальные пояснения используют требования/число тестов, конкретный Bug Proof, expected/actual/steps, фактический diff и результаты задания. Есть переходы в Test Studio, нужный Bug Proof и отчёт. Выбор Bug Proof синхронизируется с Bug Lab даже при уже открытой странице. Кнопка проверки вызывает существующий POST /bugs/{id}/verify-fix для выбранного патча. Предложение и применение исправления остаются в прежнем Bug Lab с его согласием и проверками. Companion не применяет патч сам.

Произвольного чата нет. Для будущих свободных вопросов нужен отдельно согласованный контракт: project_id, workflow_id, bug_id?, fix_id?, verification_id?, вопрос, ограниченная область передаваемых данных, согласие/лимит расходов; ответ должен возвращать ссылки на доказательства, использованную версию контекста и учёт стоимости. Такой endpoint сейчас не существует и в этой работе не создавался.

## 3D

Все GLB скопированы побайтно, SHA-256 и исходные пути в public/companion/manifest.json. Проверка сохранности в outputs/companion/preservation.json. Геометрия, кости и Morph Targets не редактировались.

- debugych_interaction.glb: утверждённый персонаж с уже настроенной лупой, 13.38 МБ. Лупа скрыта в обычном idle.
- debugych_bug_final.glb: красно-чёрный бескрылый жук с 8 лапками, 10.03 МБ. Используются scared и defeated, остальные клипы сохранены.
- debugych_seated.glb: сидячие клипы завершённого этапа, 10.36 МБ.
- debugych_chair.glb: существующее кресло, 0.136 МБ.
- debugych_laptop_optimized.glb: утверждённый ноутбук, 4.97 МБ. Экран CanvasTexture отражает переданное состояние, diff и результат проверки.
- static.png: локальный Blender-рендер исходного персонажа для fallback.

Один DebugychCompanionController и один mixer на смонтированного героя. Standing использует mixer имеющегося createHeroRig, без второго mixer. Жук имеет отдельный mixer только на время реакции. Разовые клипы сокращены до 2.8 с и crossfade 0.24 с возвращает визуальную позу в idle/hold, не меняя состояние backend. Fixing использует непрерывный typing_loop, success возвращается в seated_idle. Полная посадка не проигрывается на каждое событие. Брови, улыбка, squint и плавное закрытие/открытие век обновляются отдельным контроллером. При bug_found ободок красный, standing success зелёный. В сидячей композиции виден результат на ноутбуке, лупа не добавляется поверх стола.

## Производительность и отказоустойчивость

3D chunk и GLB загружаются лениво, жук и рабочее место только по необходимости. Предусмотрены Suspense, ErrorBoundary, статический fallback, retry, потеря контекста, reduced motion, отключение реплик и анимаций. При Hidden / mobile compact / reduced motion Canvas отсутствует. document.hidden и IntersectionObserver приостанавливают mixer и invalidate. Renderer demand, цель 24 Гц, DPR до 1.3. Skeletons, mixer, созданные материалы и CanvasTexture освобождаются. Общие неизменяемые GLTF-ресурсы сохраняются конечным URL-кешем Drei для повторного использования.

Основной JS около 334 кБ, lazy 3D chunk около 1023 кБ (gzip 280 кБ). Build сообщает предупреждение >500 кБ для lazy 3D. Совокупный размер всех GLB около 38.9 МБ, это остаётся главным ограничением загрузки на медленном соединении. Уменьшение геометрии/текстур утверждённых моделей не входило в интеграцию.

В ручной проверке IAB показано около 24 кадров/с. Headless Chromium при повторных загрузках и переключениях дал 11-16 кадров/с; это не обещание 24 FPS на всех устройствах. Warm renderer с четырьмя опорами стола после трёх циклов: 50 геометрий и 41 текстура, рост не выявлен. Измерения localhost GLB 4-60 мс отражают передачу, без гарантии времени декодирования и удалённой сети. Полный объём GPU/JS памяти и реальные слабые мобильные устройства не профилировались. Подробности в performance.json. Мобильный compact не загружает 3D.

## Ограничения

Нет нового художественного rigging или исправления унаследованных пересечений манжет/бороды. Крупная лабораторная сцена с посадкой и видео 1080p поставляется отдельно в предыдущем пакете. Переход standing/workstation меняет композицию, полноценная посадка здесь намеренно не запускается. Короткий жук появляется на полу рядом, не пролетает. Нет звука/TTS, произвольного LLM-чата и новых провайдеров. Live AI/gVisor E2E не запускались для сохранения бюджета. Требуется пользовательская оценка на целевом устройстве и медленном соединении перед merge.

## Повторная проверка

В apps/web: npm ci --offline, npm run typecheck, npm run lint, npm run test:companion, npm run build. E2E из корня: установить NODE_PATH на apps/web/node_modules, PLAYWRIGHT_BASE_URL=http://127.0.0.1:5190, запустить локальный apps/web/node_modules/@playwright/test/cli.js с --config apps/web/playwright.config.ts и companion.spec.ts. Backend unit: PYTEST_DISABLE_PLUGIN_AUTOLOAD=1, python -m pytest tests/unit -q. Использовать существующий Python venv с зависимостями проекта. Никаких LLM ключей для этих проверок не требуется.

Финальный E2E-прогон: 4/4, unexpected=0, flaky=0. Финальные warm-измерения: 15 кадров/с · 50 геометрий · 41 текстур → 16 кадров/с · 50 геометрий · 41 текстур.
