# Дебагыч

AI QA Assistant для разработчиков и QA: загрузите код и требования, получите Gherkin и исполняемые тесты, исследуйте воспроизводимое отклонение и проверьте исправление в изолированной копии.

[![checks](https://github.com/tribalsm/debugych/actions/workflows/ci.yml/badge.svg?branch=release%2Fdesktop-1.3)](https://github.com/tribalsm/debugych/actions/workflows/ci.yml?query=branch%3Arelease%2Fdesktop-1.3)

[Веб-приложение](https://debugych.89-22-232-119.sslip.io:9443/) · [Документация](docs/README.md) · [Подтверждённые проверки](docs/current-status.md) · [Если адрес не открывается](docs/public-access.md)

После входа можно загружать собственные проекты и запускать проверки. Гостевая история сохраняется в браузере 30 дней после последнего посещения и переносится в аккаунт при входе. Гость выполняет собственные pytest/Playwright-тесты или подготовленное демо; для AI-генерации нужен аккаунт и согласие на передачу очищенного кода.

## Проверяемый релиз

Актуальная версия находится в основной ветке `release/desktop-1.3`. Проверенный кандидат `fix/jury-release-demo` объединён с разрешения владельца через PR #1, merge `e6ab877`. Содержимое merge совпадает с прошедшим CI кандидатом. [Что вошло в релиз](docs/jury-release-readiness.md).

Публичный стенд показывает Python и TypeScript с частичным покрытием, Bug Proof и проверенным diff. На главной доступны исторические настоящие live AI-прогоны от 20 октября. Просмотр не запускает модель. Эти записи отделены от подготовленных контрольных тестов.

## Запуск

Поддерживаемая среда: Linux Docker Engine с зарегистрированным **gVisor/runsc** и Docker Compose 2.24.4+. Windows: используйте подготовленный Linux Docker-хост в WSL2. Настройка runtime является отдельной административной подготовкой хоста, как и установка самого Docker. Python на хосте нужен только для дополнительной диагностики ниже.

```sh
docker-compose up --build
```

Запускайте из корня репозитория. Для установки Compose в виде Docker CLI plugin эквивалентная команда: `docker compose up --build`. Дефисный entrypoint должен вызывать Compose v2, устаревший Python Compose v1 не поддерживается. В подготовке хоста `infra/install-gvisor.sh` уже предусмотрен совместимый entrypoint `docker-compose`, если его нет. Скрипт запуска приложения не обязателен. Откройте `http://127.0.0.1:8080/`, когда сервисы запустятся; журналы остаются в терминале. Для остановки используйте `docker-compose down` (или `docker compose down`) из той же папки и с тем же окружением.

Дополнительно можно выполнить `sh scripts/start-compose.sh`: он требует Python 3, заранее проверяет окружение и занятые порты и запускает именованный проект `debugych-local` в фоне с ожиданием готовности. Для его остановки: `docker compose -p debugych-local down`. Не смешивайте способы запуска для одного стенда: имена Compose-проектов могут различаться. Launcher не является обязательной частью запуска по критерию 7. [Подготовка хоста и устранение ошибок](docs/quickstart.md).

На хосте без runsc supervisor вернёт ошибку готовности, worker не запустится, пользовательские тесты выполняться не будут. Прямой Compose может успеть запустить БД/API/web; работоспособным runner такой запуск не считается. Автоматического перехода на runc, установки runtime или перезапуска Docker при старте приложения нет. Пустой Docker-хост без заранее подготовленного gVisor не поддерживается.

В CI отдельное задание `compose-direct` проверяет буквальную foreground-команду `docker-compose up --build` только с корневым Compose-файлом, без test overlay и LLM-ключа. После готовности проверяются веб-интерфейс, supervisor и исполнение загруженных pytest/Playwright-тестов в runsc. Журнал и JSON-результат доступны в артефакте `direct-compose-evidence`; полный контрактный workflow проверяется независимо в `compose-sandbox`.

Это локальное окружение разработки с loopback-портами, не публичное production-развёртывание. Для сервера с аккаунтами используйте [серверную инструкцию](docs/debugych-server-1.0.md), а не открывайте dev-порты во внешнюю сеть.

LLM-ключ для старта приложения не требуется. Для новой генерации настройте `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` в приватном окружении по [инструкции AI Engine](docs/ai-engine.md). Ключи не добавляйте в Git. Модель и общий бюджет задаются сервером; исчерпание бюджета не заменяется подготовленным ответом.

## Границы применимости

- Зависимости sandbox фиксированы; пользовательские npm scripts и pip install не запускаются. Поддерживаются pytest и браузерный Playwright-профиль с index.html в корне.
- Покрытие относится к инструментированным модулям. Если source maps недостоверны, отчёт явно помечается как compiled JS; старые измерения не переписываются.
- Java можно загрузить; исполнения Java нет. pgvector работает с локальными эмбеддингами и текстовым fallback. Индекс ограничен 160 фрагментами; поддержка произвольного monorepo не заявляется.
- Автономный live-цикл ранее подтверждён на небольших независимых Python и JS/TS контролях, а не на любых репозиториях. [Датированный отчёт](docs/archive/mvp-readiness.md).
- Неоднозначность требований останавливает автоматическую проверку. Успешный набор не доказывает отсутствие всех дефектов.
- Бесплатный адрес использует sslip.io и порт 9443. Порт 443 сохранён за VPN. Доступность из конкретной корпоративной или мобильной сети требует отдельной проверки.
