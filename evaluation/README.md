# Независимые контрольные проекты

Созданы на этом этапе, отдельно от исходных Shop/calc/Counter демонстраций. `projects/` содержит только приложение и требования. В коде приложений нет отметок места дефекта. `oracles.json` и `oracle_tests/` находятся вне загружаемых директорий; engine их не читает, в Docker-образ API они не копируются. Privacy filter дополнительно исключает пути oracle/ground-truth.

| Проект | Заложенные отклонения от документа |
| --- | --- |
| Python / FastAPI Dispatch Quotes | Неверная включительная граница цены при weight=1000; неверная бесплатная граница pickup при weight=200 |
| React / TypeScript Seat Desk | Запрет бронирования всех оставшихся мест; reset не возвращает quantity=1 |

Ключ LLM в этой сессии отсутствует. Поэтому проверялся **контрактный** workflow с подготовленными ответами, не автономное обнаружение неизвестных дефектов моделью. Первоначальный контрактный план покрывал по одному основному дефекту в каждом приложении; ещё по одному оставалось вне подготовленного плана. Это исторический результат; новый протокол приведён в `docs/benchmark.md`. Отдельные oracle-прогоны демонстрируют это на реальном исполнении. Их нельзя смешивать с метриками AI discovery.

В первом React contract-плане и первоначальном ручном oracle-чекере был ошибочный selector `getByRole('status')`: role имели и output, и message. Сохранённые сгенерированные тесты первого проекта не правились. Подготовленный provider для последующих **новых** проектов и независимый checker получили однозначный selector `p[role="status"]` с тем же ожидаемым текстом. Engine/harness также научены относить такой strict-mode сбой к ошибкам теста, исключая Confirmed. Этот неуспешный этап сохранён в отчёте.

`tests/compose/novel_projects.py` сохраняет фактические результаты и оставляет проверенные патчи **не применёнными**. В live-режиме нужен `--allow-external`; после генерации/run скрипт останавливается для ручного review. Полный путь доступен в UI. После возврата к обычному Compose без ключа отдельный запуск скрипта фиксирует `NOT_VERIFIED_API_KEY_MISSING`, не включает stub автоматически.

Контрактные schema/syntax/patch отказы проверяет `tests/compose/ai_negative_smoke.py`. Они специально сконструированы и не считаются ошибками живой LLM.


`variants.json` — приватные преобразования исправленного эталона, одно-дефектных версий и дополнительных мутаций. `tests/compose/benchmark.py` читает их только после завершения AI-ввода. Ни evaluator, ни oracle не исправляют сгенерированные тесты. Для зачёта обнаружения нужен проходящий эталон, одинаковые test/case identities и image ID, assertion-падение варианта и независимый контроль oracle. Ошибки инфраструктуры, skipped и невалидный эталон не считаются убитыми мутациями. Неоцениваемые дефекты отражаются отдельно от пропущенных.

Контрактные ответы намеренно обновлены для **новых запусков**: pickup=200 + priority и восстановление всего состояния reset теперь представлены. Это подготовленные фикстуры, написанные с известной спецификацией; сравнение до/после НЕ доказывает улучшение автономного обнаружения LLM. Исходные сохранённые проекты и тесты прошлых запусков не изменены. Новые экземпляры этих двух приложений не являются новым независимым holdout-корпусом.
